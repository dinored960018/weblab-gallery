01용어

말을 고정한다. 안 맞춰두면 AI를 갈아탈 때마다 딴소리가 나온다.

용어정의대신 쓰지 않을 말
WORK작업 1건 = 폴더 1개 = 슬롯 1칸태스크, 잡
CLONE원본 사이트를 더미 텍스트로 시각적 재현카피, 클론코딩
BUILD라이브러리를 써서 실무용 페이지 제작개발, 구현
RESEARCH월요일 리서치. 슬롯을 먹지 않는다스터디
SLOT하루 2칸. 주 5일 = 주 10칸세션
SPEC원본 해부. 그리드·타이포·컬러·간격·모션·섹션순서분석서
REVIEW재현 후 장단점과 수정안회고

CONCEPT월요일에 뽑는 7개 방향. BUILD의 원료아이디어
PROTOCOLAI가 따르는 작업 규격. 단일 원본가이드, 룰

웹 디자인 용어(타이포·모션·레이아웃)는 따로다. GLOSSARY.md에 매주 자란다. 한 번에 못 박을 게 아니라 하면서 쌓이는 것이라서.

02구조

레포를 둘로 가른다. 기준은 AI가 읽는 것과 내가 만든 것이다.

weblab-protocol · 공개

AI가 읽는 규격. 숨길 게 없고, 공개라서 인증 없이 URL로 읽힌다. 웹 ChatGPT·제미나이에 링크만 던져도 동작한다.

weblab · 비공개

만든 것. 작업물, 원본 스크린샷, 내 분석, 리서치 노트. 자동화와 갤러리도 여기.

weblab-protocol/                  ← 공개
├─ PROTOCOL.md      ★ 단일 원본. 충돌하면 이게 이긴다
├─ GLOSSARY.md        용어 사전 (매주 자람)
├─ CHECKLIST.md       완료 판정 기준
└─ templates/         SPEC / REVIEW / NOTES / CONCEPTS

weblab/                           ← 비공개
├─ CLAUDE.md · AGENTS.md · GEMINI.md   ← 규격을 가리키는 포인터
├─ works/<주차>/<종류>-<번호>-<슬러그>/
│    ├─ index.html   재현물 / 제작물
│    ├─ refs/        원본 스크린샷
│    ├─ SPEC.md      원본 해부
│    └─ REVIEW.md    장단점 + 수정안
├─ research/<주차>/
│    ├─ raw.md       자동 수집 원재료
│    └─ concepts.md  컨셉 7개 (사람이 해석)
├─ index.html        갤러리. 자동 생성
├─ scripts/          수집기 · 갤러리 생성기 (의존성 없음)
└─ .github/workflows/

멀티 AI 대응의 핵심이 여기다. 진짜 규격은 PROTOCOL.md 하나뿐이고, CLAUDE.md·AGENTS.md·GEMINI.md는 “저기 읽고 그대로 해”라는 세 줄짜리 포인터다. 규격이 한 곳에만 있어서 AI별로 어긋날 수가 없다. Grok을 붙일 땐 파일 하나만 더 만들면 된다.

03주간 사이클

월 09:00 KST  [자동]  Actions가 원재료를 모으고 이슈를 연다
월      (사람)         raw.md 읽고 CONCEPT 7개  ← 슬롯 밖
월~금            매일  CLONE 1 + BUILD 1  = 주 10칸
푸시할 때만  [자동]  works/ 를 훑어 갤러리 index.html 갱신

수집은 무인, 해석은 사람

이 경계가 이 설계의 중심이다. 해석까지 자동으로 돌리면 아무도 안 읽는 컨셉 카드가 매주 쌓인다. 그건 자동화가 아니라 쓰레기 생산이다. 그래서 기계는 원재료까지만 만들고 멈춘다.

단계누가무엇
수집ActionsSmashing · CSS-Tricks · Frontend Focus · web.dev · npm 주간 다운로드 · GitHub 신규 레포 · Hacker News
탐색AI + 브라우저Awwwards · Godly · CSSDA · Land-book · httpster — 기계로 못 읽어서 직접 본다
해석사람 + AI대화하면서 CONCEPT 7개. 방향이 겹치면 다시 뽑는다

어워드 사이트는 자동 수집이 불가능하다. 확인해봤다 — Awwwards는 RSS가 없고, Godly는 SPA라 HTML만 나오고, CSSDA는 /feed가 404를 200으로 반환한다. Codrops는 피드를 아예 내렸다(410). 어차피 눈으로 봐야 고르는 것이라 이 경계는 문제가 아니라 올바른 분업이다.

04작업 절차

CLONE

  1. 원본 확보 — 스크린샷 5장 이상(전체 1 + 섹션 4)을 refs/에
  2. 해부 — 코딩 전에 SPEC.md를 쓴다. 눈으로 본 걸 수치로 옮기는 단계
  3. 재현 — 단일 HTML. 시각적으로 똑같이. 코드 구조는 달라도 된다
  4. 대조 — refs/와 나란히 놓고 비교. “대충 비슷하다”에서 멈추지 않는다
  5. 분석 — REVIEW.md에 장점·단점·수정안. 인상평 말고 근거

BUILD

  1. 그 주 CONCEPT 중 하나를 고른다 (쓴 건 다시 안 쓴다)
  2. 그 주 리서치에서 나온 라이브러리를 최소 1개 실제로 쓴다
  3. NOTES.md에 쓴 라이브러리·막힌 지점·재사용 여부

더미 데이터

디자인을 재현하는 것이지 내용을 베끼는 게 아니다. 원본 텍스트·이미지·로고는 안 가져온다. 더미는 원본과 같은 글자 수 대역으로 맞춘다 — 길이가 다르면 레이아웃이 깨진다. Lorem ipsum은 쓰지 않는다.

쓰지 말 것

아래가 들어가면 그 작업은 실패로 친다.

  • 공허한 마케팅 문구 — “혁신적인”, “차별화된”, “최적의 솔루션”, seamless, cutting-edge. 더미 텍스트에도 안 쓴다. “빠른 배포”가 아니라 “커밋 후 40초 안에 배포”
  • 이모지 남발 — 원본에 있으면 쓰고, 없으면 안 쓴다
  • 근거 없는 REVIEW — “모던하고 세련됨”은 분석이 아니다
  • 안 해놓고 했다고 하기 — 대조를 안 했으면 안 했다고 쓴다

05작업 시작

어느 AI에게든 이 한 마디.

오늘 작업 시작

그러면 AI는 규격을 읽고 → 이번 주 폴더를 확인해 몇 번째 슬롯인지 파악하고 → 종류를 정해 확인을 받고 → 절차대로 진행한 뒤 → 체크리스트로 판정하고 커밋한다.

확인 단계는 건너뛰지 않는다. 어떤 사이트를 모작할지, 어떤 컨셉을 빌드할지는 사람이 정한다.

직접 해야 할 것 하나. Actions 워크플로를 올리려면 gh 토큰에 workflow 스코프가 필요하다. 아래를 한 번 실행하고 브라우저에서 승인하면 된다.

gh auth refresh -h github.com -s workflow

그 뒤 순서는 이렇다. 워크플로 푸시 → research/2026-W38/raw.md를 같이 읽으면서 CONCEPT 7개 → 첫 CLONE 대상 고르기 → 첫 작업.
