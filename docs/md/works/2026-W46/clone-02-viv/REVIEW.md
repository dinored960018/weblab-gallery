## 4. 장점

1. **글자 크기가 넷뿐이다.** 96px 세리프(이름 · 제목 · 선언), 43px 세리프(꼬리말 문장 · Bio), 24px 그로테스크(본문 · 큰 링크), 14px 500(머리 · 카드 제목 · 라벨). 134개 경로 어디에도 다섯 번째 크기가 없다. 작가 이름 · 글 제목 · 페이지 제목이 모두 같은 96px 라서 「어느 페이지에 있는가」보다 「누구의 무엇을 보고 있는가」가 먼저 읽힌다.
2. **색은 사진만 갖고, UI 는 사진에서 색을 빌린다.** 토큰은 `#fff` · `#000` · `#ebebeb` · `#e8e8e8`. Artists 덮개에서 이름에 올리면 페이지 바탕이, 꼬리말에서 작가 이름에 올리면 꼬리말 전체가 그 작가의 파스텔색으로 0.5초에 바뀐다. 색이 장식이 아니라 「지금 누구를 가리키고 있는가」의 표시다.
3. **메뉴가 곧 목록이다.** Artists 는 드롭다운이 아니라 화면 전체를 쓰는 페이지고, 9명의 이름이 96px 로 끝없이 돈다. 이름에 올리면 화면 가운데에 대표 사진이 1.2초(`.16,1,.3,1`)에 열리고, 왼쪽의 Photography / Motion / Creative 중 그 작가가 하지 않는 분야가 25% 로 흐려진다. 클릭 없이 「누가 무엇을 하는가」를 훑는 필터가 된다.
4. **틀 일곱 개로 134경로.** 뉴스 · 프로덕션 · 디렉터 프로젝트 목록은 같은 3단 벽돌 쌓기(463px, 세로 60, 14px 제목)이고, 세 종류의 글도 같은 틀(제목 → 전폭 사진 → 글 50% + Client 25% + Role 25% → 홀로 선 사진 · 4단 갤러리 → Next)이다. Production 제목 하나만 오른쪽에 붙여 구분한다. 틀이 같아 49개 뉴스와 16개 사례가 한 사이트로 읽힌다.
5. **작가 페이지의 조작이 막대 하나에 있다.** 화면 아래 가운데의 283×54 검정 막대에 Work · Bio · Contact 와 격자 2종이 모여 있다. 분류는 이름 옆 「All (188)」을 누르면 격자를 밀어 내리며 펼쳐진다(덮지 않는다). 사진 위에 UI 가 올라가는 순간이 없다.
6. **확대 보기에 UI 가 없다.** 사진이 썸네일 자리에서 가운데로 0.55초에 날아오고 바탕이 흰색으로 덮일 뿐이다. 버튼 · 캡션 틀 · 어두운 막이 없어 포트폴리오를 넘기는 동안 사진만 남는다.
7. **All 은 여백이 넓다.** 칸 10vw 에 간격 8vw — 칸과 간격이 거의 같다. 80장이 작게, 띄엄띄엄 깔려 작가 구분 없이 사진의 결만 비교된다. 확대하면 짧은 변이 화면의 75% 가 되고 왼쪽 아래에 작가 이름 하나가 뜬다.
8. **꼬리말이 페이지의 끝 장면이다.** 모든 페이지가 100svh 꼬리말로 끝나고, 안쪽이 −25% 에서 올라오며 어두운 막이 50% → 10% 로 걷힌다. 절반 넘게 드러나면 머리가 사라져 로고 · 선언 · 작가 9명만 남는다.

## 5. 단점

1. **스크롤이 `main` 안에 있다.** `body{overflow:hidden}` · `main{height:100svh;overflow:auto}`. 문서 높이가 어느 페이지나 900 이라(실측) 브라우저의 스크롤 복원, 모바일 주소창 접힘, 페이지 전체 캡처 · 인쇄가 문서 기준으로 동작하지 않는다. 포커스가 `main` 밖에 있으면 키보드 스크롤도 먹지 않는다.
2. **홈 맨 위에서 스크롤이 잠긴다.** 가만히 두면 3초 뒤 사진 순환이 시작되고, 순환하는 2–5초 동안 Lenis 를 멈춘다(원본 스크립트). 그때 휠을 굴리면 「다음 바퀴에서 멈추라」는 표시만 남고 화면은 움직이지 않는다.
3. **포커스 표시가 없다.** `:focus{outline:none}` · `a:focus-visible{outline:none}`(원본 스타일시트). 확대 보기는 `role` 도 포커스 이동도 없고, Artists 의 분야 글자는 눌러도 아무 일 없는 `<button>` 이다. 제목은 h1 다음 h3. Developer Award 의 Accessibility 는 7.20.
4. **목록이 한 번에 다 온다.** News 49건이 쪽 나눔 · 필터 없이 11023px(12화면), 390px 에서는 24779px(29화면)이다. 작가별로 걸러 볼 수 없다. All 은 80장을 2×2 로 복제해 `<img>` 320개 + 영상 64개를 `loading="eager"` 로 올린다.
5. **모바일 메뉴가 열려도 뒤가 스크롤된다.** `main` 의 `overflow` 가 `auto` 그대로다(실측). 메뉴 판 아래로 내용이 흘러간다.
6. **들어갈 길이 없는 페이지.** `/directors` 는 사이트맵에만 있다. 디렉터는 Artists 목록에 작가와 섞여 있고 URL 만 `/director/` 다.
7. **분류를 바꿀 때마다 페이지를 새로 받는다.** 분류 판의 항목은 링크(`/artist/x/sports`)라 판이 닫히고 0.65초, 격자가 꺼지고 0.4초, 그다음에 새 페이지를 받는다. 사진 13장을 거르는 데 1초가 넘게 걸린다.

## 6. 수정안

1. 스크롤을 문서로 되돌린다(`html` 스크롤 + Lenis 기본 래퍼). 꼬리말 시차는 `position:sticky; bottom:0` 으로 같은 결과가 나온다. 모작은 원본 구조를 지키되 `main` 에 `tabindex="-1"` 포커스를 줘 키보드 스크롤이 먹게 했다.
2. 순환 중에도 스크롤을 받는다 — 휠이 들어오면 순환을 그 자리에서 멈춘다(모작 적용). 순환 시작도 3초 → 5초로 늦추면 첫 스크롤과 겹칠 일이 줄어든다.
3. `:focus-visible{outline:2px solid #000; outline-offset:3px}`(검정 막대 안은 흰색), 확대 보기에 `role="dialog"` · 포커스 가둠 · 복귀 · 숨은 Previous / Next / Close 버튼, 분야 글자는 `<p>`, 카드 · 이름 제목은 h2(모작 전부 적용).
4. News 는 24건씩 Load more(작가 페이지와 같은 버튼), 위에 작가 이름 9개를 14px 로 깔아 필터로 쓴다. All 은 화면에 들어온 칸만 그리면 DOM 이 80개로 끝난다(모작 적용 — 칸이 위치를 돌려 쓴다).
5. 메뉴가 열린 동안 `main{overflow:hidden}` + Lenis 정지, Esc 로 닫힘(모작 적용).
6. `/directors` 를 지우고 `/artist/` 로 합치거나, Artists 덮개의 분야 글자(Creative)를 누르면 디렉터만 남게 한다.
7. 분류는 같은 페이지에서 거른다 — 판을 닫는 0.65초 동안 격자를 다시 쌓고(Flip 0.7s 를 그대로 쓸 수 있다) URL 은 `history.replaceState` 로 바꾼다. 대기 1.05초 + 로드가 0.65초로 준다.

## 7. 왜 상을 받았나

- **Content 7.55 · Design 7.47 이 가장 높다.** 내용이 곧 사진이고, 디자인은 사진을 방해하지 않는 데 쓰였다. 색 없는 UI, 네 가지 글자 크기, 사진 위에 올라가지 않는 조작. 사진 에이전시 사이트가 흔히 하는 풀블리드 슬라이더 · 검은 바탕 · 자동 재생 릴 대신 흰 바탕에 띄엄띄엄 놓은 썸네일을 골랐다.
- **가장 위험한 선택**: 메뉴를 페이지로 만든 것(Artists 덮개)과 All — 설명 글자 하나 없이 80장만 깔린 끝없는 판. 둘 다 「목록」이라는 관행을 버렸지만, 9명 · 80장이라는 적은 수와 96px 이름 · 10vw 칸이라는 큰 단위 덕에 길을 잃지 않는다.
- **가장 많은 공이 들어간 곳**: 작가 페이지. 격자 2종의 Flip 전환, 격자를 밀어 내리는 분류 판, 썸네일에서 날아오는 확대, 꼬리말 앞에서 물러나는 막대 — 조작이 넷인데 화면에 보이는 UI 는 막대 하나다. 재현에서도 여기가 가장 오래 걸렸다.
- **Developer Award 7.3 — WPO 7.60 · Semantics 7.60.** Astro 정적 HTML + 88KB 스타일시트 하나, 사진마다 대표색을 인라인으로 깔고 0.5초 페이드. Animations 7.00 은 개발 항목 중 가장 낮다 — 모션은 등장 · 전환 · hover 에만 있고 길지 않다.
- **Usability 7.05 가 가장 낮다.** 위 단점 1(안쪽 스크롤) · 2(스크롤 잠김) · 4(걸러 볼 수 없는 49건) · 6(숨은 페이지)과 맞는다.
- **모작해보고 알게 된 것**: 홈의 사진 띠는 화면보다 30% 넓고(130vw) 마우스 x 를 따라 좌우로 민다. 정지 화면에서는 「잘린 사진 다섯 줄」로만 보이지만, 양끝 기둥이 늘 잘려 있어 「옆에 더 있다」는 신호가 된다. 그리고 그 띠가 스크롤보다 1.5배 빨리 올라가서, 96px 문장이 나타날 때는 사진이 이미 화면을 비운다 — 띠 아래를 −30vw 겹쳐 놓고 시차로 푸는 구조다.

## 10. 재현하면서 배운 것

- **화면보다 넓은 요소는 「잘라 그리기」로 바꿀 수 있다.** 130vw 띠와 4147px 판을 그대로 두면 게이트(오른쪽 넘침)에 걸린다. 상자는 화면 끝에서 자르고 그림은 `::before` 가 원래 폭으로 그리게 하면 보이는 결과가 같다. All 은 그 김에 화면 밖 칸을 아예 그리지 않게 돼 DOM 이 320 → 80개로 줄었다.
- **hover 를 `@media (hover:hover)` 로 걸면 자동화 브라우저에서 전부 꺼질 수 있다.** 녹화 도구의 Chrome 은 마우스가 있어도 이 조건이 거짓이었다. 원본처럼 터치 지원 여부로 클래스를 붙이는 쪽이 도구와 실제 양쪽에서 같다.
- **대체 서체는 폭을 재서 크기로 맞춘다.** Libre Caslon Condensed 는 Garamond Narrow 보다 12% 넓다. 크기를 96 → 90px 로, 줄 상자는 96px 그대로 두니 줄바꿈과 블록 높이가 원본과 같아졌다(about −0.5%).
- **표지 사진의 가로 · 세로 비가 목록 길이를 정한다.** 49건 중 13건의 표지를 세로 → 가로로 바꾼 것만으로 News 가 +15.8% → +2.6% 가 됐다.
- **모션의 절반은 CSS 에 안 보인다.** 원본 CSS 전환은 `ease` 0.5s 가 대부분이고, 홈 등장 · 순환 · 확대 · 판 이동은 전부 GSAP 인라인이다. `motion.json` 의 인라인 스타일 기록과 원본 스크립트의 지속시간 · 이징 값을 같이 봐야 표가 채워진다.

## 11. 어긋난 채로 남은 것

- 영상(Mux) 전부 — 사진으로 대신.
- swup 페이지 전환 — 보통 이동.
- 세리프의 획 굵기(대체 서체에 가는 굵기가 없다).
- 디렉터 프로젝트 글 −17.0% · Big Game 글 −22.7%(사진 수).
- `/artists` 에서 숨은 머리의 밑줄이 한 번 열리는 전환 1건(모션 비교 빨강 1).
- All 확대 뒤 고해상도 교체, 판 이동 곡선(quickTo → 지수 감쇠).
- 홈 순환 중 스크롤 잠금은 일부러 옮기지 않았다.
