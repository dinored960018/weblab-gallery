## 4. 장점

- **두 서체의 대비만으로 위계를 만든다.** 화면 전체가 흑백 두 색인데, 가늘고 좁은 세리프(감정)와 굵은 그로테스크(주장)를 한 문장 안에서 섞어 강조를 만든다. 색을 쓰지 않으니 사례 사진이 들어오는 순간 그 색이 가장 강한 신호가 된다.
- **6칸 210/20 그리드를 끝까지 지킨다.** 메뉴 밑줄 6개가 곧 그리드 표시라, 아래의 모든 칸(2단 문구 670, 쇼릴 900, 글 블록 440, 서비스 3단)이 메뉴 칸 경계에 맞아 떨어지는 것이 눈에 보인다.
- **목록이 정보 표처럼 읽힌다.** 사례 행은 번호 · 이름 · 수상 · 범위를 네 모서리에 고정해 행끼리 같은 위치를 비교할 수 있다. 사진은 hover 때만 나와 목록이 길어도 무겁지 않다.
- **모션이 적고 정확하다.** 로드 스크램블 1.3초, 마퀴 30초 한 가지, hover 는 `all ease` 하나. 움직이는 요소가 3종뿐이라 무엇이 살아 있는지 바로 안다.

## 5. 단점

- **본문 가독성.** 12px 고정폭 대문자, 17px/17px(행간 1.0) 양끝맞춤 대문자 문단은 영어 단어 모양(어센더·디센더)을 지워 읽는 속도를 떨어뜨린다. 양끝맞춤에 하이픈이 없어 좁은 칸(325–440px)에서 단어 사이가 크게 벌어진다(히어로 아래 2단 "TO   CONNECT").
- **hover 의존.** 홈 사례 행의 사진은 hover 때만 보여 터치 기기·키보드 사용자는 행이 왜 341px 인지 모른다(원본 데스크톱에서 행 대부분이 빈 칸).
- **포커스 표시 없음.** 원본은 `a:hover, a:active { outline: 0 }` · `.w-*:focus { outline: 0 }` 로 포커스 링을 지운다. 키보드로 위치를 알 수 없다.
- **문서 길이.** 사례 상세가 11,000–13,000px(12–14화면)인데 글 블록은 3–5개뿐이라 사진 사이 이동이 길다.

## 6. 수정안

- 리드 문단: 17px 행간을 1.0 → 1.25(21px)로, 칸 폭 440 → 520 으로 넓혀 단어 사이 벌어짐을 줄인다. 하이픈을 켜거나(`hyphens:auto`), 2단 문구만 양끝맞춤을 유지하고 문단은 왼쪽 정렬로.
- 모노 본문: 12px → 13px(원본 토큰 `--s-a-mono-font-default: 13px` 이 이미 있다), 문장형 설명은 소문자로.
- 홈 사례 행: 터치 기기(`hover:none`)에서는 사진을 행 가운데(210칸)에 고정 노출 — 모작 390px 처리처럼.
- 포커스: 1px 검정 outline + offset 3px(모작에 넣은 값).
- 사례 상세: 글 블록 사이 스페이서 200 → 140, 같은 구도의 사진 블록 두 개가 연달아 오면 하나로 합쳐 문서를 약 20% 줄인다.

## 7. 왜 상을 받았나

- **타이포그래피만으로 정체성을 세웠다.** 로고 없이 문장 하나(히어로)가 회사 소개 · 등급 · 분야를 다 말하고, 같은 서체 대비가 푸터 마퀴(세리프 · 이탤릭 · 굵게)에서 다시 나와 처음과 끝이 묶인다. Awwwards 태그(Clean · Minimal · Typography)가 정확히 이 점이다.
- **포트폴리오의 증거를 구조로 보여 준다.** 사례마다 수상 · 범위를 같은 자리에 두고 수상 목록을 홈과 소개에 반복해, 심사 기준 중 "콘텐츠" 점수에 직접 닿는다.
- **절제된 인터랙션의 완성도.** 스크램블 · 커서 사진 · 마퀴 셋 다 짧고 끊김이 없으며 원본 측정에서 스크롤 하이재킹도 없다. 화려함보다 완성도를 보는 SOTD 심사에서 "사용성"과 "디자인" 점수를 함께 얻는 구성이다.
