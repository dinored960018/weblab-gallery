## 왜 상을 받았나

- **가장 위험한 선택**: 목록을 목록처럼 보이지 않게 했다. 건축가 8명을 카드 그리드나 표로 늘어놓는 대신 **색인 탭이 달린 파일 폴더 더미** 하나로 만들었다. 이름을 읽으려면 탭을 봐야 하고, 분류 설명은 폴더를 벌려야 보인다. 정보가 숨어 있는 셈인데, 폴더를 들추는 동작 자체가 "기록 보관소를 뒤진다"는 주제와 같아서 통했다. 첫 화면에서 탐색 비용이 들지만 탭 8개라 감당된다.
- **가장 많은 공이 들어간 곳**: 탭 클릭 뒤 1.3 초 안무. 다른 그룹이 앞쪽부터 떨어지고, 같은 그룹의 다른 탭이 가라앉고, 페이지가 바뀌는 순간 **방금 누른 그룹이 -90° 누운 채 그대로 이어져** 세로로 선 폴더가 되고, 표지가 책처럼 넘어가 종이 시트가 드러난다. 두 화면(홈 스택의 가로 폴더, 케이스의 세로 폴더)을 같은 물건으로 묶는 연출이라 SPA 로 만들었을 것이다. 재현하면서 시간이 가장 오래 걸린 곳도 여기다.
- **모작해보고 알게 된 것**:
  1. 스택의 입체감은 **3도**에서 나온다. `rotateX(-3deg)` + `perspective: 3000px` + 높이 -1rem. 호버한 그룹 앞의 그룹만 숙이고, 같은 그룹 안에서는 호버한 쪽 앞의 쪽만 숙인다. 이 규칙 하나로 "손가락으로 파일을 벌리는" 느낌이 난다. 원본 클래스 변화를 그대로 표로 옮겼더니 기하값까지 원본과 한 픽셀도 다르지 않게 나왔다(`hover-states-*.txt` 일치).
  2. 오른쪽 33% 에 보이지 않는 `unfold-area` 가 있다. 포인터가 오른쪽으로 가면 앞 그룹들이 156px(15vw - 60) 더 내려가 분류 설명이 드러난다. 눈으로 봐서는 알 수 없었고 `elementFromPoint` 로 찾았다.
  3. 케이스 스크랩북은 "자유 배치"처럼 보이지만 조각마다 **앵커(메모) + 위성(사진·클립)** 구조이고 위치가 `calc(p% - p×폭)` 식으로 폴더 크기에 비례한다. 폴더 폭 기준으로 좌표를 재서 옮기니 8개 케이스 문서 높이가 원본과 정확히 같아졌다.
  4. "Keep scrolling for the next page" 진행 막대는 **휠이 잠시 멈추면 비워진다.** 120 ms 간격이면 차오르고 그보다 길면 초기화 — 우연히 끝에 닿은 사람이 다음 페이지로 넘어가지 않게 하는 장치다.

## 장점

- **무엇**: 분류가 곧 내비게이션이다.
  **왜 작동하나**: 4개 분류 × 탭 8개가 한 화면(1440×900 에서 스택 top 504, 탭 행 간격 60px)에 다 들어간다. 따로 메뉴가 없다. 색이 탭마다 달라서(파랑·빨강·초록·보라·노랑·검정) 두 번째 방문부터는 색으로 찾는다.
- **무엇**: 전환이 공간을 설명한다.
  **왜 작동하나**: 홈의 가로 폴더와 케이스의 세로 폴더는 같은 요소가 90° 돈 것이다. 세로 탭(오른쪽 모서리)이 홈 탭 행과 같은 순서라서, 케이스 안에서 형제 건축가로 이동할 때 사용자가 새 위치를 배울 필요가 없다.
- **무엇**: 스크랩북이 긴 글을 대신한다.
  **왜 작동하나**: 건물마다 메모 1장(제목 + 150자 안팎)과 사진 2~4장. 글 분량을 억제하고 대신 사진을 끌어서 옮겨 보게 한다. 드래그 경계가 폴더 폭 × 1.1 로 제한돼 조각을 잃어버리지 않는다.
- **무엇**: 끝에서 다음으로 가는 흐름.
  **왜 작동하나**: 문서 끝에 다음 건축가 폴더 머리가 55vh 로 보이고, 고정 위젯이 이름·분류를 알려 준다. 8명을 순환(Sullivan → Wright)하므로 막다른 끝이 없다.

## 단점

- **무엇**: 폴더 스택 호버 상태가 포인터 전용이다.
  **어떤 문제를 만드나**: 원본은 키보드 포커스로 스택을 벌리지 않고(실측: Tab 으로 탭 링크에 포커스해도 클래스 변화 없음), 390px 터치에서는 분류 설명을 볼 방법이 없다(`.stack-cover__desc` 가 480px 이하에서 `display:none`). 모작은 포커스에도 같은 상태를 걸었지만 원본 기준으로는 접근성 결함.
- **무엇**: 팝업이 ESC 로 닫히지 않는다(원본 실측, `rec-case.json`).
  **어떤 문제를 만드나**: 포커스는 body 에 남고 `role` 도 없다(실측). 키보드 사용자는 닫기 버튼까지 Tab 으로 찾아가야 한다. 모작은 ESC · 포커스 가둠 · 포커스 복귀를 추가했다.
- **무엇**: 대비 부족.
  **어떤 문제를 만드나**: 히어로 설명 `#787a7f` on `#191919` = 4.09:1, About 서명 `#b4b4b4` on `#fdfaf7` = 2.0:1, 팝업 출처 opacity .5. 본문 4.5:1 미달.
- **무엇**: 스크랩북 조각이 서로를 가린다.
  **어떤 문제를 만드나**: 메모 본문이 사진에 덮여 끝까지 읽히지 않는 곳이 케이스마다 1~2곳 있다(예: Wright 메모 1, Gehry 메모 1). 드래그로 치울 수 있지만 드래그 가능하다는 표시가 `cursor: grab` 뿐이다.
- **무엇**: 성능.
  **어떤 문제를 만드나**: 원본 JS 번들 1,009 KB(`origin.md`), 케이스 페이지 AVIF 10~16장. 스택 전환이 `height` 트랜지션이라 호버마다 레이아웃이 다시 계산된다.

## 수정안

- **어디를**: 스택 키보드·터치
  **어떻게**: 탭 링크 `:focus-visible` 에 호버와 같은 상태를 걸고(모작에 적용), 터치에서는 첫 탭은 폴더 벌리기, 두 번째 탭은 이동으로 나눈다. 480px 이하에서 분류 설명을 12px 캡션 2줄로 남긴다.
  **왜 나아지나**: 분류 설명이 모든 입력 방식에서 읽힌다.
- **어디를**: 팝업
  **어떻게**: `role="dialog"` · `aria-modal` · ESC · 닫기 버튼 초기 포커스 · 닫은 뒤 원래 조각으로 포커스 복귀(모작에 적용).
  **왜 나아지나**: 키보드로 열고 닫는 최소선 충족.
- **어디를**: 대비
  **어떻게**: 히어로 설명 `#8e9095`(5.50:1), 서명 `#6b6b6b`(5.12:1), 출처 opacity .8(5.0:1) — 모작에 적용.
- **어디를**: 스택 높이 트랜지션
  **어떻게**: 그룹 높이 대신 `translateY` 로 같은 거리(12px / 156px)를 옮기고, 그룹 바닥을 `clip-path` 로 자른다.
  **왜 나아지나**: 호버마다 레이아웃 재계산이 없어진다. 화면은 같다.
- **어디를**: 스크랩북 겹침
  **어떻게**: 메모가 가려지면 호버 시 메모를 z 맨 위로 올리고(드래그 시작 때 이미 하는 동작), 조각 위에 4초간 "Drag" 힌트를 한 번만 띄운다.

## 재현하면서 배운 것

- 스크린샷 두 장으로는 스택 규칙을 절대 못 맞춘다. **탭마다 호버하며 클래스와 높이를 덤프**하니 규칙이 표 한 장으로 정리됐다. 모션 모작에서 "상태 표"가 프레임보다 먼저다.
- GSAP 인라인 값을 시간순으로 샘플링하면 이징을 역산할 수 있다. 폴더 회전은 21% 시점에 2.4%, 50% 시점에 50% — 대칭 inOut 이고 지수는 3과 4 사이(3.5)였다.
- 원본의 "자유 배치" 스크랩북은 폴더 폭 비례 좌표라서, 폭 단위(`cqw`)로 옮기면 반응형까지 같이 따라온다.
- 사진 검수는 작게 보면 놓친다. CC 배지가 찍힌 사진을 한 번 채택했다가 85장 전체를 크게 다시 보는 단계에서 찾았다.

## 어긋난 채로 남은 것

- **영상·오디오 내용**: 실존 인터뷰 영상과 55분 녹음 대신 빈 플레이어와 25초 룸톤.
- **케이스 초상**: 실존 건축가 얼굴 대신 얼굴 없는 제도 사진. 원본 첫인상(시트 왼쪽 위 초상)이 다르다.
- **사진 내용 정합**: 메모의 건물과 옆 사진이 같은 건물이 아닌 곳이 있다(예: Pei 의 Bank of China 메모 옆 사진은 Louvre). 캡션은 사진에 보이는 것만 적어 사실과 어긋나지 않게 했다.
- **메모 질감**: 원본의 스캔한 종이 마스크·얼룩(AVIF) 대신 SVG 노이즈와 직접 그린 찢김 마스크. 가까이 보면 덜 거칠다.
- **About 높이**: 2187 / 2366 (92%) — 본문 분량 차.
- **모바일 스크랩북**: 원본은 조각을 세로로 흘려 배치하는 별도 규칙이 있고, 모작은 데스크톱 배치를 묶음별로 축소·세로 나열했다. 문서 높이 2623 / 3000(87%).
- **record-motion 케이스 서명 3줄**(진행 막대·폭·색 전환): SPEC "남은 빨간 줄" 참고. 폭·진행 막대는 기능 테스트와 프레임으로 동작 확인, 색 전환은 SPA 전용.
- **Lenis**: 원본과 같은 라이브러리를 CDN 으로 씀(직접 구현 아님).
