# REVIEW — STUDIO OFF-BEAT (오프비트)

- **어워드**: Awwwards Honorable Mention (2026-03-18) · https://www.awwwards.com/sites/studio-off-beat
- **모작**: HALF-REST / 하프레스트 (가상 스튜디오) · 149페이지

---

## 왜 상을 받았나

사진 스튜디오 포트폴리오는 보통 사진 격자 하나로 끝난다. 오프비트는 같은 사진들을 **세 가지 속도로 보여 주는 구조**를 만들었고, 심사는 그 편집을 봤다고 본다.

- **가장 위험한 선택**: 홈에서 작업을 사진이 아니라 **금색 72px 이름 목록**으로 보여 준 것. 포트폴리오 홈인데 첫 4,000px 동안 작업 사진이 한 장도 안 나오고, Featured 세 구간도 사진 격자 대신 이름만 30줄씩 늘어놓았다. 사진은 커서가 이름 위에 올라갈 때만 170px 크기로 열린다. 통한 이유는 바탕색이다. Projects 에서 적갈(#641e1e), Stages 에서 흑갈(#2d2415)로 스크롤에 따라 바탕이 바뀌어서, 같은 모양의 목록 세 개가 서로 다른 방으로 읽힌다.
- **가장 공들인 곳**: 홈 첫 세 화면. 로고 글자 → 막이 걷히며 메트로놈 사진이 아래에서 올라옴 → 사진이 0.92배로 물러나며 어두워지고 → 식물 사진이 그 위를 덮으며 문장이 글자 단위로 10° 기울어 올라왔다가 빠진다. 스튜디오 이름(엇박)을 박자와 시간의 모션으로 번역한 구간이다. 녹화해 보니 이 구간만 GSAP 인라인 스타일 변화가 160개 요소에서 일어난다.
- **모작해 보고 알게 된 것**: 목록 페이지(Portrait·Project)의 배경 얼룩은 WebGL 이지만 3D 가 아니라 **노이즈 임계값 셰이더 한 장**이다. 캔버스 2D 로 1/12 해상도에서 계산해 확대해도 화면에서는 구분이 안 된다. 이 사이트의 ‘기술적 인상’ 대부분은 GPU 가 아니라 **이징 두 개**(등장 cubic-bezier(.16,1,.3,1) 1200ms, 내비 숨김 (.7,0,.3,1) 360ms)에서 나온다.

## 장점

- **무엇**: 스크롤에 따라 바뀌는 바탕색(#0a0a0a → #641e1e → #2d2415 → #0a0a0a).
  **왜 작동하나**: 섹션 경계선이나 제목 장식 없이 지금 어느 분류를 보고 있는지 알려 준다. 세 구간의 제목·문단·목록 배치가 거의 같은데도 헷갈리지 않는 이유다.
- **무엇**: 필터를 세 그룹(year · type · beat)으로 나누고 그룹끼리 AND 로 건다.
  **왜 작동하나**: 60건 목록이 2~3번 누르면 한 자릿수로 줄어든다. 특히 ‘beat’(Largo~Prestissimo)는 촬영 분위기를 템포 기호로 분류한 것이라 형용사 태그(‘차분한’, ‘역동적인’)보다 기준이 분명하다.
- **무엇**: 상세 페이지를 한 화면(900px)에 넣었다 — 왼쪽 썸네일 15개 · 정보 표, 오른쪽 뷰어 681px.
  **왜 작동하나**: 스크롤 없이 사진 15장을 넘겨 볼 수 있고, 클릭하면 바로 라이트박스로 커진다. 상세 페이지가 길어지는 포트폴리오의 흔한 문제를 피했다.
- **무엇**: 본문을 한국어·영어 두 벌로 같은 칸에 나란히(justify, 18px) 놓았다.
  **왜 작동하나**: 언어 전환 버튼이 없고, 두 문단이 대각선으로 엇갈려 놓여 그 자체가 레이아웃 장치가 된다.

## 단점

- **무엇**: 필터에서 선택된 버튼이 화면에 표시되지 않는다. `aria-pressed` 는 바뀌지만 글자색·밑줄은 그대로다(`refs/states/portrait-filter-solo-2024.jpg`: solo·2024 를 눌렀는데 겉모습이 다른 버튼과 같다).
  **어떤 문제를 만드나**: 세 그룹을 조합한 뒤 어떤 조건이 걸려 있는지 다시 볼 방법이 없다. 결과 수 표시도 없어 0건일 때 빈 화면만 남는다.
- **무엇**: 히어로 제목·리드 문장 자간 −0.06em, 행간 1.0~1.2.
  **어떤 문제를 만드나**: 56px 에서는 버티지만 768~1100px 구간에서도 같은 값이라 단어 사이가 붙는다. 대비 검사기도 이 값을 잡는다.
- **무엇**: 인트로 2.3초 + 로고 1.4초 + 막 1.6초 = 첫 화면까지 약 5.5초. 매 방문마다 재생된다.
  **어떤 문제를 만드나**: 다른 페이지에서 홈으로 돌아올 때마다 같은 5초를 기다린다. 건너뛰기 수단이 없다.
- **무엇**: 홈 Featured 목록에서 사진은 마우스 호버로만 열린다.
  **어떤 문제를 만드나**: 터치 기기에서는 이름 30줄만 보이고 사진을 볼 방법이 없다(탭하면 바로 상세로 넘어간다).
- **무엇**: 폼 오류를 브라우저 기본 말풍선에만 맡기고, 라벨이 12.25px #888.
  **어떤 문제를 만드나**: 여러 칸이 비어도 첫 칸 하나만 알려 준다. 라벨은 대비는 통과(5.58:1)하지만 크기가 작아 칸 이름을 읽기 어렵다.

## 수정안

- **어디를**: 필터
  **어떻게**: 선택된 버튼에 1px 밑줄 고정(모작 반영), 그룹 아래 ‘N개’ 결과 수, 0건이면 안내 문장(모작 반영).
  **왜 나아지나**: 걸린 조건과 결과를 한눈에 확인한다.
- **어디를**: 인트로
  **어떻게**: 세션당 한 번만 재생(sessionStorage), 두 번째부터 막 페이드 400ms 로 대체. 클릭·키 입력 시 즉시 건너뛰기.
  **왜 나아지나**: 첫 방문 인상은 그대로 두고, 재방문 대기 5.5초 → 0.4초.
- **어디를**: 홈 Featured 목록 (터치)
  **어떻게**: `(hover: none)` 에서 이름 오른쪽에 64px 썸네일을 상시 표시.
  **왜 나아지나**: 터치 기기에서도 이름과 사진을 함께 본다.
- **어디를**: 리드 문장 자간
  **어떻게**: `letter-spacing: clamp(-0.06em, -0.02em - 0.4vw, -0.03em)` 처럼 화면이 좁을수록 덜 좁힌다.
  **왜 나아지나**: 넓은 화면의 인상은 유지하고 좁은 화면 판독성을 확보한다.
- **어디를**: 문의 폼
  **어떻게**: 칸 아래 오류 문장 · `aria-invalid` · 첫 오류 칸 포커스(모작 반영), 라벨 12.25 → 14px.
  **왜 나아지나**: 비어 있는 칸을 한 번에 다 알 수 있다.

## 재현하면서 배운 것

- 원본의 모션 39건(홈) 중 CSS 전환은 9종뿐이고 나머지는 전부 GSAP 인라인 스타일이었다. 녹화기 ‘서명 비교’에서 원본에만 있는 줄이 0이 되어도, 실제 느낌은 인라인 스타일 표(시작·끝 값)를 옮겼는지에서 갈렸다. 히어로 0.92배·막 0.95·식물 clip 181px→0 같은 수치를 그대로 쓰니 스크린샷 대조에서 같은 프레임이 나왔다.
- 원본 카드 호버 키프레임은 교차 출처 시트라 처음엔 못 읽었지만, 녹화기가 실행 중인 애니메이션의 키프레임을 잡아 왔다(opacity 0 → .35 → .12). ‘못 읽는다’고 적기 전에 녹화를 먼저 봐야 한다.
- 스크립트 시작 시각은 내비게이션 시작보다 약 390ms 늦다(CDN 서체·Lenis 로드). 인트로를 원본 시각에 맞추려면 setTimeout 값이 아니라 녹화된 시각으로 맞춰야 한다. 세 번 고쳐서 ±100ms 로 들어왔다.
- `String.replace` 의 치환 문자열에서 `$$` 는 `$` 한 개가 된다. 코드를 문자열 치환으로 고치다가 `$$('.card')` 가 `$('.card')` 로 바뀌어 필터가 통째로 멈췄다. 기능 테스트를 수정마다 다시 돌려서 잡았다.
- 사진 풀 크기(45)와 갤러리 추출 보폭(5)이 서로소가 아니어서 생성기가 무한 반복에 빠졌다. 데이터 개수를 늘릴 때는 이런 산술 가정을 같이 봐야 한다.

## 어긋난 채로 남은 것

- **사진의 성격**: 원본 Portrait 는 얼굴 정면 인물 사진 60장이다. 모작은 실존 인물 얼굴을 쓰지 않는 규칙 때문에 뒷모습·실루엣·손·흐린 동작만 썼다. 격자의 리듬(4열·1:1)은 같지만, ‘표정을 찍는 스튜디오’라는 원본의 핵심은 사진으로 전달되지 않는다.
- **Stage 포스터**: 원본은 디자인된 포스터 이미지, 모작은 무대 사진 + CSS 조판.
- **목록 수**: Portrait 60 → 44, Project 약 210 → 88(문서 높이 86% · 85%).
- **인터뷰 1건 높이 75%**: 원본 도빛 인터뷰(4,630자, 사진 19장)보다 짧다.
- **WebGL → 캔버스 2D**: 결과 화면은 같지만 셰이더의 `u_pulse` 계수 같은 값은 모른다(유니폼 값은 프레임마다 JS 가 넣어서 소스에 없음). 얼룩 크기·속도는 화면을 보고 맞췄다.
- **마퀴 스크롤 연동 계수**: 추정값.
- **barba 전환**: 실제 페이지 이동이라 원본처럼 내비가 유지된 채 내용만 바뀌지는 않는다.
