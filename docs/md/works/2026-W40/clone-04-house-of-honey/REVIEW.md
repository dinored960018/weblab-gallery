# REVIEW — House of Honey

- **어워드**: Awwwards Site of the Day (2026-07-14) · https://www.awwwards.com/sites/house-of-honey-1
- **모작**: `Parlor of Plum` 36페이지 · `build.mjs` 로 생성

## 왜 상을 받았나

- **가장 위험한 선택**: 모든 페이지 제목 뒤에 **글자 높이 537px 짜리 분홍 스크립트가 흘러간다**. 제목(61px 세리프 대문자)을 반쯤 가리고 지나간다. 가독성으로만 보면 실수인데, 스크립트가 28px/s 로 아주 느리게 움직이고 색이 한 가지(#fc72c4)라서 "배경 무늬"로 읽힌다. 세리프 제목은 가만히 있고 스크립트만 흐르니 둘이 싸우지 않는다. 브랜드의 "과감한 우아함"이 로고 없이도 페이지마다 선다.
- **가장 많은 공이 들어간 곳**: 첫 화면 슬라이드. 들어오는 사진이 오른쪽에서 clip-path 로 닦이며 1.072 배에서 1 배로, 0.45° 기울었다가 바로 선다. 나가는 사진은 반대로 2.4% 밀리며 0.958 배로 작아지고 -0.35° 기운다. 1.87 초 동안 두 장이 동시에 다른 방향으로 움직여서 "책장을 넘기는" 느낌이 난다. 수치가 작아 따로 보이지는 않지만, 두 장이 반대 방향으로 조금씩 움직이는 것이 평범한 와이프와의 차이다.
- **모작해보고 알게 된 것**:
  - 원본은 **색 두 개(#edccbe, #331917)와 강조 하나(#fc72c4)** 로 36페이지를 전부 해결한다. 섹션마다 밝음/어둠만 뒤집는다. 그래서 사진이 아무리 알록달록해도 사이트가 흐트러지지 않는다.
  - 내비는 "탭"이다. 각 링크가 blush 사각형이고, 호버하면 25px 알약으로 둥글어지며 분홍으로 바뀐다(0.4 s). 스크롤해도 사진 위에 떠 있어서 헤더 배경이 필요 없다.
  - 줄 단위 등장(8px, 0.8 s, 줄마다 80 ms)은 문장이 길수록 효과가 크다. 짧은 라벨은 거의 티가 안 난다 — 원본이 제목보다 문단·주소·푸터 링크까지 줄 분할을 거는 이유.
  - 벌 커서(40×40 캔버스)는 기능이 아니라 이름값이다. Honey → 벌. 모작에서 Plum 으로 바꾸고 나니 벌의 근거가 약해졌다(자두꽃 수분 정도).

## 장점

- **무엇**: 세 서체의 역할 분리 — 스크립트(장식, 움직임), 세리프 대문자(제목, 정지), 그로테스크(정보).
  **왜 작동하나**: 크기 대역이 겹치지 않는다. 스크립트 250~580px, 세리프 24~64px, 그로테스크 14~22px. 한 화면에 셋이 있어도 위계가 크기만으로 정해진다. 모든 크기가 `min + (max-min)·(100vw-375)/1225` 한 식으로 늘어나 모바일에서도 비율이 유지된다.
- **무엇**: 사진 위 글자는 항상 brown 50% 덮개를 거친다.
  **왜 작동하나**: 사진 명도와 상관없이 blush/흰 글자의 대비가 확보된다. 스토리 6장이 모두 다른 사진인데 한 묶음으로 보인다.
- **무엇**: 그리드 사이에 끼운 인용 카드(분홍 점 두 개 + 세리프 한 줄).
  **왜 작동하나**: 사진 카드와 같은 4:5 상자라 리듬이 깨지지 않으면서, 13개 프로젝트 목록이 "카탈로그"가 아니라 "잡지 지면"처럼 읽힌다.
- **무엇**: 인트로가 1.2 초짜리 검은 막 하나.
  **왜 작동하나**: 로더 그래픽 없이 폰트·첫 사진이 준비될 시간을 번다. 첫 로드에만 나와서 페이지 이동 때 방해하지 않는다.

## 단점

- **무엇**: 보조 글자(좌표, "Read more", 푸터 링크)를 `opacity .6` 으로 흐린다.
  **어떤 문제를 만드나**: blush 바탕 위 brown 60% = **3.9:1**. 본문 크기(14~16px)라 WCAG AA(4.5:1) 미달.
- **무엇**: 537px 스크립트 마퀴가 모든 페이지에서 멈추지 않는다.
  **어떤 문제를 만드나**: 정지 버튼이 없고, 원본 DOM 에서 `motion-reduce:` 클래스는 인트로 막과 메뉴 버튼에만 있고 마퀴에는 없다(`prefers-reduced-motion` 에서 실제로 도는지는 녹화하지 않았다). 전정기관 민감 사용자에게 부담.
- **무엇**: 프로젝트 카드 대부분이 자동재생 영상(mux).
  **어떤 문제를 만드나**: 목록 한 화면에 영상 6~9개가 동시에 재생된다. 헤드리스 녹화에서 카드가 빈 칸으로 남을 만큼 로딩이 무겁다(`refs/motion-origin` 스크롤 프레임). 저사양·모바일 데이터에 불리.
- **무엇**: 갤러리 "사진 열기" 가 `<a href="?lightbox=…&index=n">` 이다.
  **어떤 문제를 만드나**: 기능은 모달인데 링크라서 사진마다 별도 URL 이 생기고 크롤러가 같은 페이지를 수십 번 방문한다. 스크린리더도 "링크"로 읽는다.
- **무엇**: 대문자 세리프 문단(퍼스펙티브 4문단, 인용 블록).
  **어떤 문제를 만드나**: 138자 대문자 문단은 단어 모양이 사라져 읽는 속도가 떨어진다.

## 수정안

- **어디를**: 보조 글자 불투명도
  **어떻게**: `.6` → `.7` (모작 적용). 또는 색을 `#6b4a44` 로 고정.
  **왜 나아지나**: 3.9:1 → 5.1:1. 인상은 거의 같다.
- **어디를**: 마퀴
  **어떻게**: `prefers-reduced-motion` 에서 `animation: none` (모작 적용), 그리고 화면 밖 섹션은 `animation-play-state: paused`.
  **왜 나아지나**: 접근성 + 보이지 않는 6개 마퀴의 합성 비용 제거.
- **어디를**: 목록 카드 영상
  **어떻게**: 포스터 이미지를 기본으로, 카드가 화면 50% 이상 들어왔을 때만 재생, 동시 재생 2개 제한.
  **왜 나아지나**: 초기 전송량이 카드 수에 비례해 늘지 않는다.
- **어디를**: 갤러리 열기
  **어떻게**: `<button aria-haspopup="dialog">` 로 열고, 열린 동안만 `history.replaceState` 로 `?photo=n` (모작 적용).
  **왜 나아지나**: 딥링크는 유지하면서 링크 남발이 사라진다.
- **어디를**: 대문자 문단
  **어떻게**: 첫 문장만 대문자, 나머지는 문장형 대소문자 + 행간 1.3.
  **왜 나아지나**: 지면 인상은 남기고 긴 문단 판독성을 회복.

## 재현하면서 배운 것

- 슬라이드 곡선은 녹화 프레임만으로는 안 나온다. 페이지 안에서 rAF 로 `style` 을 매 프레임 읽어(`refs/states/hero-slideshow-samples.txt`) 중간 지점 진행률(50% 시점 51%)을 보고서야 `(.7,0,.25,1)` 로 확정했다.
- 원본 갤러리 확대 아이콘은 호버가 아니라 **화면 안에 들어온 사진에 뜬다**. 녹화기 커서가 여백(x=2)에 있었는데도 350 ms 페이드가 28번 기록돼서 알았다.
- 마퀴 지속시간은 텍스트 폭에 비례한다(112 s ÷ 폭 ≈ 28 px/s). 고정 초로 두면 짧은 단어("404")가 미친 듯이 빨라진다.
- `overflow:hidden` 대신 `clip-path` 로 마스크를 바꾸면 scale 된 자식이 **가로 스크롤을 만든다**. 변형된 상자는 스크롤 넘침에 들어간다. `contain: paint` 가 둘 다 해결.
- 세리프 제목은 `font-weight` 기본값(bold) 때문에 가짜 볼드가 됐었다. 원본 noeText 는 400 한 벌뿐이라 h1~h4 를 400 으로 고정해야 같은 무게가 된다.

## 어긋난 채로 남은 것

- **영상**: 원본 카드·갤러리의 mux 자동재생 영상은 사진으로 대체.
- **사진 품질**: Pinterest 결과 상당수가 AI 렌더라 스톡으로 보충했다. 채택 58장 중 욕실 3장·거실 1장은 렌더 가능성을 완전히 배제하지 못했다. 갤러리는 58장 풀을 순환해서 프로젝트끼리 같은 사진이 다시 나온다(한 프로젝트 안에서는 중복 없음).
- **워드마크**: 원본은 손으로 그린 SVG 로고, 모작은 Archivo Expanded Black + Pinyon Script 조판. 글자 폭을 `textLength` 로 늘려서 원본보다 글자가 약간 좁고 높다.
- **스크립트 서체**: Pinyon Script 는 canora 보다 획이 조금 두껍고 대문자 스와시가 짧다.
- **프라이버시 페이지**: 원본 대비 68% 높이(법률 문안 분량 미재현).
- **Lenis 관성 스크롤**: 생략(원본도 `looksHijacked` 네이티브 판정).
