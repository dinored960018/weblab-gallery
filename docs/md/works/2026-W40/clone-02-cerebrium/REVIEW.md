## 왜 상을 받았나

### 가장 위험한 선택 — 인프라 회사가 첫 화면을 "그림"에 줬다

GPU 인프라 사이트의 첫 화면은 보통 대시보드 스크린샷이나 코드 블록이다. 여기는 화면의 3/4을 3D 리본에 내주고,
제목은 좌하단 662px 칸에, 부제와 버튼은 오른쪽 아래 340px 칸에 밀어 넣었다. 제품이 무엇인지는 첫 화면에서 거의 말하지 않는다.

**왜 통했나**: 이 회사가 파는 건 "눈에 안 보이는 것"(콜드스타트 2~4초, 오토스케일)이다. 보여줄 화면이 없는 제품이라
**속도와 규모를 형태로 번역**했다. 그리고 *Click and hold* 로 그 형태를 직접 조작하게 한다. 누르고 있으면 UI가 사라지고
카메라가 리본 사이로 빨려 들어가며 `Quickly → Scale → Globally` 가 뜬다. 카피 세 단어를 읽는 게 아니라 **체감**하게 만든다.
심사가 본 건 이 한 동작일 가능성이 크다. 다른 인프라 사이트에 없는 것이다.

### 가장 많은 공이 들어간 곳 — 캔버스 한 장 위로 패널이 올라오는 구조

배경은 `position:fixed` 캔버스 하나이고, 흰 패널(3,679px)과 슬레이트 패널(2,593px)이 **32px 모서리로 60px씩 겹쳐** 올라온다.
패널 사이의 다크 구간(보안 2,342px)에서만 캔버스가 드러나고, 드러날 때마다 장면이 리본 → 구체 → 리본(푸터)으로 바뀐다.
재현에서 제일 오래 걸린 것도 여기다. 장면을 스크롤 위치로 고르는 규칙(`[data-scene]` 중 화면 점유가 가장 큰 블록)을 정하고,
패널이 캔버스를 덮는 동안에는 그리기를 건너뛰게 해야 했다.

### 모작해보고 알게 된 것

1. **흰 면이 대부분인데 다크 사이트로 기억된다.** 홈 10,870px 중 캔버스가 보이는 건 히어로 1,545 + 보안 2,342 + 푸터 891 = 4,778px(44%)뿐이다.
   그런데 세 구간이 **시작·중간·끝**에 놓여 있어서 인상은 다크로 남는다. 순서가 비율을 이긴다.
2. **모노 라벨 13px이 사이트의 목소리다.** 내비, 버튼, 섹션 라벨, 날짜, 태그가 전부 Suisse Mono 13px 대문자(`-0.325px`)다.
   디스플레이 서체(Favorit 300)가 가볍고 둥근 만큼, 모노가 "엔지니어링 도구"라는 톤을 혼자 짊어진다. 대체 서체를 IBM Plex Mono로 바꿨을 때 이 톤이 가장 먼저 흔들렸다.
3. **스크램블 호버가 모노와 짝이다.** 내비 글자가 호버 때 무작위 글자로 뒤섞였다 돌아온다. 가변폭 서체였다면 글자폭이 바뀌어 메뉴가 흔들렸을 것이다. 모노라서 가능한 효과다.

## 장점

### 1. 가격 페이지가 계산기까지 한 화면 흐름으로 이어진다
**무엇**: 좌측 슬레이트(제목·설명) / 우측 캔버스 위 단가표(11행) → 초/시간 토글 → 플랜 3장 → 비교표 → 계산기 → FAQ.
**왜 작동하나**: 초당 가격 `$0.000306/s` 는 감이 안 오는 숫자다. 토글 한 번으로 `$1.10/hr` 로 바꿔주고, 아래 계산기가
요청 수(로그 스케일 1~5,000,000) × 런타임 × 하드웨어로 **월 금액**까지 풀어준다. 추상적인 단가 → 익숙한 단위 → 내 사용량 순서라 의심이 생기는 지점마다 답이 있다.

### 2. 스티키 목록 + 카드 4장으로 "Why" 를 한 번에 훑게 한다
**무엇**: 왼쪽에 44px 목록 4줄(비활성 `#c6cee0`), 오른쪽에 562px 비주얼 카드. 스크롤하면 해당 항목만 네이비로 켜진다.
**왜 작동하나**: 목록이 목차이자 진행 표시다. 4개 중 몇 번째인지 항상 보이니 1,900px 넘는 구간이 길게 느껴지지 않는다.
비주얼도 전부 **제품 화면의 축약**(콜드스타트 막대, GPU 지도, 터미널, 메트릭 차트)이라 마케팅 그림이 아니라 증거로 읽힌다.

### 3. 강조를 그라디언트 한 단어로만 한다
**무엇**: `#ff488b → #e33adb` (oklab 보간) 그라디언트가 제목마다 **한 구절**에만 들어간다(`scales`, `pushing boundaries`, `secure`, `real-time AI`).
**왜 작동하나**: 제목 7~8개가 모두 같은 규칙이라 스캔하면 핑크 단어만 이어 읽어도 요지가 나온다. 핑크 버튼(`#ff488b` + 차콜 글자)과 같은 색이라 "강조 = 행동" 이 한 체계로 묶인다.

### 4. 쿠키 동의를 제대로 만들었다
**무엇**: 배너(수락/거절/설정) → 설정 모달(카테고리 펼침, 토글, 필수는 잠김). Google Analytics 는 동의 전엔 안 돈다고 명시.
**왜 작동하나**: "거절"이 "수락"과 같은 크기·같은 줄에 있다(172×42 / 165×42, 실측 스크린샷 기준). 다크 패턴이 없다. 브랜드 색(핑크·네이비·슬레이트)도 그대로 입혀 이질감이 없다.

## 단점

### 1. 핑크 위 흰 글자, 연한 칩 위 흰 글자 (실측)
**무엇**: 차트 범례 `P90` 흰 글자 on `#90aade` = **2.3:1**, `P50` on `#7a7fb2` = 3.8:1, `MAX` on `#ff488b` = 3.2:1. 터미널 성공 줄 `#ff488b` on 흰색 90% = **2.6:1**.
**어떤 문제를 만드나**: 범례와 로그는 "읽어야 하는" 정보다. 특히 터미널은 이 섹션의 메시지(코드 그대로 돌아간다)를 담은 줄인데 가장 흐리다. `impeccable detect` 에서 남은 9건 중 7건이 이것이다.

### 2. 드롭다운에 `aria-expanded` 가 없다
**무엇**: `Use cases` 버튼 실측 `aria-expanded = null`. 호버·클릭으로 열리지만 상태를 알리지 않는다.
**어떤 문제를 만드나**: 스크린리더 사용자는 메뉴가 열렸는지 모른다. 열리면 본문 전체가 블러 처리되는데, 그 사실도 전달되지 않는다.

### 3. 히어로의 핵심 경험이 마우스 전용이다
**무엇**: *Click and hold* 는 포인터를 누르고 있어야만 동작한다. 모바일은 ▶ 영상 버튼으로 대신한다.
**어떤 문제를 만드나**: 키보드 사용자와 대부분의 태블릿 사용자는 사이트의 대표 장면(속도·규모의 체감)을 못 본다. 심사가 가장 높이 샀을 부분이 가장 적은 사람에게만 열려 있다.

### 4. 성능 비용이 크다
**무엇**: 배경 스크립트 344KB, 캡처 구간 드로우 콜 7,937회, 버퍼 약 12MB. 흰 패널이 화면을 완전히 덮고 있을 때도 캔버스가 계속 돈다(fixed).
**어떤 문제를 만드나**: 저사양 노트북·모바일에서 스크롤 중 프레임이 떨어진다. 인프라 회사가 "빠름"을 파는데 사이트 자체가 무겁다는 모순.

### 5. 블로그 h1이 숨어 있다
**무엇**: `/blog` 의 h1은 `sr-only` 16px, 보이는 제목이 없다(실측). 첫 화면이 바로 추천 글 카드다.
**어떤 문제를 만드나**: 페이지에 들어와서 "여기가 어디인지" 를 알려주는 텍스트가 헤더 내비 밑줄(BLOG) 하나뿐이다. 검색으로 바로 들어온 사람에게 약하다.

## 수정안

### 1. 범례·터미널 색을 한 단계 내린다
```css
--legend-p50: #5b6199;   /* 흰 글자 5.8:1 */
--legend-p90: #4d6fb4;   /* 흰 글자 4.9:1 */
--legend-max: #d4165c;   /* 흰 글자 5.2:1 */
--term-ok:    #c8104f;   /* 흰 90% 위 4.7:1 */
```
차트 선 색도 같이 바꾼다. 핑크 CTA 버튼은 글자가 차콜이라 그대로 둔다(5.8:1).
**왜 나아지나**: 브랜드 색상 계열은 유지하면서 읽어야 하는 데이터만 AA를 넘긴다.

### 2. 드롭다운에 상태를 붙인다
`aria-expanded` + `aria-controls`, `↓` 로 첫 링크 포커스, `ESC` 로 닫고 버튼 복귀. **모작에는 넣었다** (Playwright로 확인).

### 3. Click and hold 를 키보드로도
히어로에 포커스 가능한 버튼을 하나 두고 `Space` 누르고 있는 동안 같은 효과를 준다. `prefers-reduced-motion` 에서는 세 단어를 정적으로 한 번 보여준다.
**왜 나아지나**: 대표 경험이 입력 수단에 묶이지 않는다.

### 4. 캔버스를 보이는 구간에서만 그린다
`IntersectionObserver` 로 다크 구간이 화면에 없으면 `requestAnimationFrame` 에서 그리기를 건너뛴다. **모작은 이렇게 했다** (`visible` 플래그).
흰 패널 구간(홈의 약 56%)에서 GPU 부하가 0이 된다.

### 5. 블로그에 보이는 제목 한 줄
추천 카드 위 40px 높이로 `Engineering blog` 모노 라벨(13px) 한 줄. 레이아웃 높이 +40px, 첫 화면 구성은 유지.

## 재현하면서 배운 것

1. **`visibility` 전환은 열릴 때 0s 로 줘야 포커스가 들어간다.** `transition: visibility .2s` 를 열림에도 걸어두면 첫 프레임에 아직 `hidden` 이라 `focus()` 가 무시된다. 드롭다운 `↓` 키가 첫 링크로 안 가서 알았다.
2. **호버로 열리는 메뉴에 클릭 토글을 붙이면 "호버 → 클릭 = 닫힘" 이 된다.** 마우스로 누르는 사람에겐 메뉴가 깜빡 사라진다. 호버로 연 지 400ms 안의 클릭은 무시하게 했다.
3. **HTML `pattern` 은 이제 `v` 플래그로 컴파일된다.** `[+0-9 ()-]` 가 문법 오류가 되어 조용히 무시됐다(콘솔 에러 1줄). 전화번호 검증이 통째로 꺼져 있었다.
4. **탐지기가 원본의 선택과 내 선택을 가려준다.** 536건 중 527건은 내 흔적이었다(Geist, 패딩, `width` 전환, `overflow-x:clip` 등). 남은 9건은 전부 원본에서 실측한 색·구조였다. 모작에서 탐지기는 "원본과 다르게 만든 곳" 탐지기이기도 하다.
5. **`python` 이 없는 환경에서 `python` 이 조용히 성공한다.** 윈도우 스토어 스텁이 "Python" 한 줄만 찍고 종료해서, 패치가 적용 안 된 채 한동안 캐시된 화면을 보고 있었다. 빌드 파일에 버전 쿼리(`?v=`)를 붙이고, 수정은 Node/Edit 로만 했다.
