# REVIEW — 블루보틀 커피 코리아

- **어워드**: Awwwards Honorable Mention (2026-01-31) · https://www.awwwards.com/sites/bule-bottle-coffee-korea

---

## 왜 상을 받았나

Honorable Mention 은 SOTD 아래 등급이다. 모션·실험으로 받은 상이 아니라 **Shopify 기본 테마(Dawn) 위에서 브랜드 톤을 끝까지 지킨 커머스**로 받은 상으로 본다. 녹화해 보니 원본에서 움직이는 건 공지 바 슬라이드, 헤더 숨김, 슬라이더 화살표, 이미지 페이드, 드로어 넷뿐이다. 이징도 `ease` 와 Dawn 기본 곡선 둘뿐이다.

- **가장 위험한 선택**: 한국어 라벨 자간을 **1.68px(0.12em)** 로 넓힌 것. 한글은 보통 자간을 좁히는데, 이 사이트는 버튼·라벨·푸터 링크를 모두 벌렸다. 한글이 영문 대문자 라벨처럼 읽혀 "조용한 매장 간판" 인상이 난다. `impeccable detect` 가 74페이지에서 `wide-tracking` 으로 잡을 정도로 관행을 어긴 지점인데, 벌린 글자가 전부 2~8자 라벨이라 가독성 손해가 거의 없어서 통했다.
- **가장 많은 공이 들어간 곳**: 여백 수치. 홈 섹션 높이가 820 · 709 · 901 · 904 · 904 · 1081 로, 제목·버튼 위치가 섹션마다 158/159·128·140·156 같은 큰 값으로 고정돼 있다. 모작하면서 가장 오래 걸린 것도 이 수치를 맞추는 일이었다(최종 문서 높이 6,068 vs 6,035, 섹션 6개 중 5개 픽셀 단위 일치).
- **모작해보고 알게 된 것**: 원본 인상의 절반은 **상품 사진의 통일성**이다. 원본 상품 컷은 전부 같은 조명·같은 크림 바탕 `#f9f6f0` 의 누끼라 카드 그리드가 하나의 면으로 읽힌다. 스톡 사진으로 채운 모작 컬렉션은 레이아웃 수치가 같아도 사진 톤이 제각각이라 훨씬 산만하다. 이 사이트의 디자인 시스템은 CSS 가 아니라 촬영 가이드에 있다.

## 장점

- **무엇**: 라벨 한 가지 스타일(14px · 500 · 자간 1.68px)을 버튼·eyebrow·카드 유형·푸터 제목에 반복.
  **왜 작동하나**: 크기 단계가 40 / 30 / 24 / 18 / 16 / 14 / 12 로 적고, 역할을 굵기와 자간으로 나눈다. 폰트도 Noto Sans KR 하나라 요소 수가 적어도 위계가 선다.
- **무엇**: 쇼핑 메뉴를 호버 메가메뉴가 아닌 **클릭 드로어**(왼쪽에서 200ms)로.
  **왜 작동하나**: 헤더 항목이 4개뿐이라 호버 오작동이 없고, 드로어가 500px 씩 옆으로 펼쳐져 2단 분류(5개 → 3~7개)를 한 화면에 둔다. 모바일 메뉴와 같은 컴포넌트를 쓰므로 데스크톱·모바일 구조가 같다.
- **무엇**: 원두 카드 호버에서 두 번째 사진 대신 **풍미 노트와 로스팅 단계**를 보여 줌.
  **왜 작동하나**: 원두는 봉투 사진이 다 비슷해 두 번째 사진이 정보가 없다. 같은 자리에 구매 결정 정보를 넣었다.
- **무엇**: 헤더가 아래로 스크롤하면 숨고(500ms) 위로 올리면 돌아옴.
  **왜 작동하나**: 사진 면적이 큰 사이트라 80px 헤더를 걷으면 첫 화면에서 사진이 차지하는 높이가 약 10% 늘어난다.

## 단점

- **무엇**: 히어로·카페 레일 화살표가 18×34px 흰 사각이고 **영역에 마우스를 올려야 나타난다**.
  **어떤 문제를 만드나**: 조작성. 터치 기기에는 호버가 없어 화살표를 볼 수 없고, 데스크톱에서도 클릭 표적이 WCAG 2.5.8 권장 24×24 보다 작다. 번호 `01 02` 가 12px 로 유일한 대안이다.
- **무엇**: 공지 바가 5초마다 자동으로 넘어가고 정지 버튼이 없다.
  **어떤 문제를 만드나**: 접근성(WCAG 2.2.2). 무료 배송 조건 같은 필수 정보가 읽는 도중 사라진다.
- **무엇**: 배경 사진 위 배너 글자가 `#6c6864` (회갈색) 24px/18px.
  **어떤 문제를 만드나**: 가독성. 원본 사진의 밝은 베이지 영역 위에서 대비가 약 4:1 수준으로 떨어진다. 사진이 바뀌면 보장되지 않는다.
- **무엇**: 원본 드로어·검색 버튼에 `aria-expanded` 가 없고, 헤더 쇼핑 항목이 `li` 에 클릭 핸들러가 달린 구조.
  **어떤 문제를 만드나**: 키보드·스크린리더 사용자가 메뉴 상태를 알 수 없다(모작은 `button` + `aria-expanded` 로 바꿈).
- **무엇**: 카페 목록 24곳을 지역 구분 없이 한 그리드로.
  **어떤 문제를 만드나**: 정보 위계. 부산에 사는 사람이 3곳을 찾으려면 5,845px 를 훑어야 한다.

## 수정안

- **어디를**: 슬라이더 화살표
  **어떻게**: 18×34 → **44×44**, 항상 보이되 opacity 0.6, 호버 1.0. 번호는 12px → 14px.
  **왜 나아지나**: 터치에서도 보이고, 표적 크기가 44px 로 권장치를 넘는다.
- **어디를**: 공지 바
  **어떻게**: 자동 넘김 간격 5s → 8s, 오른쪽 끝에 16px 일시정지 버튼, 호버·포커스 시 정지(모작에 반영).
  **왜 나아지나**: 2.2.2 충족, 긴 문구도 끝까지 읽힌다.
- **어디를**: 배경 배너 글자
  **어떻게**: `#6c6864` → `#4a4744` (모작 반영), 또는 텍스트 뒤 `rgba(253,251,247,.72)` 면 24px 안쪽 여백.
  **왜 나아지나**: 밝은 사진 위 대비 7:1 이상.
- **어디를**: 카페 목록
  **어떻게**: 지역 칩(전체·서울·경기·인천·부산·대구·제주) + 개수. 모작에는 넣지 않았다(원본에 없는 기능, PROTOCOL §4-4).
  **왜 나아지나**: 한 번 클릭으로 목록이 1/4~1/12 로 줄어든다.
- **어디를**: 상품 사진
  **어떻게**: 모작에서도 촬영 규칙을 먼저 정한다 — 크림 바탕 `#f9f6f0`, 45° 왼쪽 위 광원, 상품이 정사각 프레임의 55%.
  **왜 나아지나**: 위 "모작해보고 알게 된 것" — 그리드 통일성은 사진 규칙에서 나온다.

## 재현하면서 배운 것

- Dawn 테마 사이트는 모션 녹화에서 서명이 5~7종밖에 안 나온다. 모션을 "더" 넣으면 오히려 원본에서 멀어진다. 등장 애니메이션을 하나도 넣지 않은 게 맞는 판단이었다.
- 섹션 높이를 픽셀 단위로 맞추면(709·901·904) 사진이 달라도 스크롤 리듬이 원본과 같게 느껴진다. 반대로 사진 톤이 다르면 리듬이 같아도 인상이 다르다.
- 흰 글자가 올라가는 자리는 명도 30 이하 사진이 필요하다. 명도 37 사진(히어로 2)도 제목 아래쪽이 어두워서 통과했지만 여유가 적다.

## 어긋난 채로 남은 것

- 상품 사진 톤 불일치(위). 스톡에서 같은 조명의 누끼 세트를 구할 수 없었다.
- 가로로 넓은 칸 일부(카페 레일·블로그)는 Pixabay 사진이라 해상도·색감이 핀 사진보다 거칠다.
- 상품 상세의 "테이스팅 노트" 5블렌드 차트 섹션 생략(원본이 이미지 차트).
- 컬렉션 문서 높이 124%(한 쪽 24개), 카페·블로그·FAQ 는 항목 수가 원본보다 적어 더 짧다.
- Swiper 마우스 드래그 없음(터치 스와이프만).
- 녹화 비교에서 원본에만 있는 서명 3종(드로어 초기화, 화살표 도중 역재생, Shopify 결제 스켈레톤) — SPEC 에 이유.
