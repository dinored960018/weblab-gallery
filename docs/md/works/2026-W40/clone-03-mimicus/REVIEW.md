# REVIEW — MIMICUS

- **어워드**: Awwwards Honorable Mention (2019-06-20) · https://www.awwwards.com/sites/mimicus-inc
- **모작**: 필로 / PHYLLO (가상), 30페이지(한국어 15 + 영문 15). 라이브 사이트는 수상 이후 Wix로 다시 만든 버전이라, 여기서 보는 것은 2026-09-30의 사이트다.

---

## 왜 상을 받았나

2019년 수상 버전은 남아 있지 않다. 아래는 지금 사이트에서 확인되는 것으로, 같은 운영사가 유지해 온 성격이라고 보고 적는다.

- **가장 위험한 선택**: 자료실 사이트인데 홈의 절반을 **스크롤로 넘기는 이야기**에 썼다. 부엉이 사진 하나에서 시작해 팬터그래프 사진으로 넘어가고, 그 위로 "교육 / 컨설팅 / 지식서비스" 카드가 지나간다. 검색창 하나로 끝낼 수 있는 자료실을 "한 사례 → 세 가지 이용 방법"으로 풀어 보여 준다. 다른 논문·특허 DB 사이트는 검색창과 목록으로 시작한다.
- **가장 많은 공이 들어간 곳**: 스탯 패널 4장. 1260px 섹션 안에 900px 레이어 두 장(사진, 글)을 sticky로 붙여, 다음 패널이 앞 패널을 덮으며 올라온다. 숫자는 블롭·마름모·별 같은 도형 안에 들어 있고 들어올 때 옆으로 접혀 펴진다(foldIn). 재현에서도 이 구간(5040px)을 맞추는 데 시간이 가장 오래 걸렸다.
- **모작해 보고 알게 된 것**: 움직임은 거의 전부 **sticky 배치**에서 나온다. 스크롤 연동 transform은 하나도 없고(실측 "모션 곡선 없음"), 진입 애니메이션도 1.2초짜리 네 종류뿐이다. 레이어를 어디에 붙이고 몇 px 동안 붙여 두는지가 연출의 전부다.

## 장점

- **무엇**: 자료 목록의 카드 규칙이 하나다.
  **왜 작동하나**: 사례·논문·특허·교육 자료가 모두 "Most Visited 가로 카드 2장 → 격자/목록 → 페이지 번호" 순서이고, 카드는 반경 20px · 그림자 `0 1px 12px rgba(0,0,0,.18)` 하나로 통일되어 있다. 페이지를 옮겨도 읽는 순서가 같아 학습 비용이 없다.
- **무엇**: 논문 카드의 오른쪽 종(種) 상자.
  **왜 작동하나**: 본문 1030px 옆 250px 상자에 학명(이탤릭)과 일반명을 붙여, "이 논문이 어떤 생물을 다루는가"를 제목을 읽기 전에 보여 준다. 자연모방이라는 주제를 목록 형식 자체로 드러낸다.
- **무엇**: 검색을 두 방식으로 나누고 자리표시로 설명한다.
  **왜 작동하나**: Keyword는 `"Surface"`, Semantic은 `"How to reduce high-speed train noise?"` 를 자리표시로 보여 준다. 설명 문장 없이 입력 예시만으로 두 방식의 차이가 전달된다.
- **무엇**: sticky 2단 서비스 블록.
  **왜 작동하나**: 왼쪽(무엇을 하는가 + 이력 + 신청 버튼)이 고정되고 오른쪽(세부 과정)만 흘러, 긴 설명을 읽는 동안 신청 버튼이 화면에서 사라지지 않는다.

## 단점

- **무엇**: 대비. 현재 내비 `#38c68b`(흰 바탕 2.2:1), 호버 `#bada55`(1.6:1), 날짜 `#a8a8a8`(2.4:1), 스탯 도형 `#a4a896` 위 흰 글자, 출처 9.9px 색 글씨.
  **어떤 문제를 만드나**: 현재 위치 표시와 날짜가 저시력 사용자에게 안 보인다. WCAG AA(4.5:1) 미달.
- **무엇**: 사례 상세가 URL 없는 모달.
  **어떤 문제를 만드나**: 사례를 공유하거나 북마크할 수 없고, 새로고침하면 목록으로 돌아간다. 뒤로 가기도 모달을 닫지 않는다.
- **무엇**: 한 페이지 안에 한국어와 영어가 층 없이 섞인다(제목 "Biomimetics Case Studies | 자연모방 사례", 폼 라벨 "First name 이름", 컨설팅 이력은 영어, 교육 이력은 한국어).
  **어떤 문제를 만드나**: 어느 쪽이 주 언어인지 흐려지고, 스크린리더가 `lang` 전환 없이 읽는다.
- **무엇**: 폼 오류가 색으로만 표시된다(분홍 면 + 빨간 테두리, 문장 없음).
  **어떤 문제를 만드나**: 색각 이상 사용자와 스크린리더 사용자는 무엇이 틀렸는지 모른다.
- **무엇**: 본문 줄높이 1.2배(Wix 기본), 행 길이 약 70자(서비스 본문 672px × 16.2px).
  **어떤 문제를 만드나**: 한글 본문이 빽빽해 줄을 놓치기 쉽다.
- **무엇**: 문구가 과장형("신박한", "무궁무진한", "파괴적인 툴", "혁신의 기회").
  **어떤 문제를 만드나**: 자료실의 신뢰와 어긋난다. 같은 자리에 수치가 있으면(99.8%, 8.7M) 형용사가 필요 없다.

## 수정안

- **어디를**: 내비·날짜·도형 색
  **어떻게**: 현재 `#1f7a52`, 호버 `#5d7412`, 날짜 `#767676`, 도형 `#676d57`(모작에 적용)
  **왜 나아지나**: 모두 4.5:1 이상. 색상 계열은 원본과 같아 인상은 유지된다.
- **어디를**: 사례 모달
  **어떻게**: 열 때 `#slug` 를 주소에 넣고, 해시로 들어오면 모달을 바로 연다(모작에 적용). 한 단계 더 가면 `/articles/<slug>` 정적 페이지를 두고 모달은 그 페이지를 불러오는 방식.
  **왜 나아지나**: 공유·새로고침·뒤로 가기가 모두 동작한다.
- **어디를**: 폼 오류
  **어떻게**: 필드 아래 18px 줄에 오류 문장을 넣고(`aria-describedby`), 제출 시 첫 오류로 포커스, 상단 요약 문장(`role=status`). 오류 줄 높이를 미리 잡아 두어 레이아웃이 밀리지 않게 한다(모작에서 실제로 오류가 사라질 때 제출 버튼이 올라가 클릭이 빗나가는 버그를 겪고 이렇게 고쳤다).
  **왜 나아지나**: 색 없이도 원인이 읽히고, 수정 중 버튼 위치가 고정된다.
- **어디를**: 서비스·목록 본문
  **어떻게**: 줄높이 1.5, 본문 폭 600px(약 36자)
  **왜 나아지나**: 한글 권장 측정폭(25~40자)에 들어온다.

## 재현하면서 배운 것

- Wix 진입 애니메이션은 요소마다 **두 애니메이션을 동시에** 건다(slideIn + fadeIn, foldIn + fadeIn). `getAnimations()` 목록만 보면 한 요소에 두 줄이 나와 중복처럼 보이는데, 실제로 둘 다 필요하다. 첫 녹화 비교에서 fade 짝이 빠진 것이 "원본에만" 서명으로 드러났다.
- 진입 애니메이션의 이징은 `motion.json` 에는 `linear` 로 찍힌다. 실제 곡선은 요소의 `animation-timing-function` computed 값에 있다. 녹화 기록만 믿었으면 전부 linear로 만들었을 것이다.
- sticky 연출은 "무엇을 고정하나"보다 "**고정 구간 길이**"가 인상을 정한다. 흰개미 섹션 왼쪽 글이 1850px 동안 붙어 있어야 다크 카드와 흰 카드가 나란히 선다.

## 어긋난 채로 남은 것

- 서비스 페이지 높이 87%, 특허 88% — 원본의 교육 도식·앱 화면이 큰 이미지라서. 모작은 HTML 도식이 더 짧다.
- 모달·라이트박스 열림 전환은 원본 수치를 녹화하지 못해 400ms 페이드로 추정했다.
- Semantic 검색은 원본 서버 AI 검색이 아니라 단어 일치 근사다.
- 사진 32장은 Pinterest 원 게시자 저작물로 라이선스가 확인되지 않았다(핀 주소 기록).
