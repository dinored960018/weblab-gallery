## 4. 장점

- **"우주(#00040e) ↔ 흰 무대" 두 바탕만 번갈아 쓴다.** 홈은 KV(우주) → 소개(흰) → 미션(우주) → 제품(흰) 순서로 900px 마다 바탕이 뒤집힌다. 사진 주제가 바뀌어도 바탕이 둘뿐이라 7화면이 한 장면처럼 이어진다. 하위 페이지도 같은 규칙(Discover·Protect 는 우주 쪽, IR·ESG 는 흰 쪽)이라 메뉴를 모르고 들어가도 "어느 쪽 이야기인가"가 바탕색으로 먼저 읽힌다.
- **글자 크기가 화면폭에 비례한다.** `html{font-size:.88vw}` 하나로 모든 rem 이 함께 커지고, 작은 글자만 `clamp(13px,…)` 로 바닥을 둔다. 1440 과 1920 에서 한 화면에 들어오는 구성이 같아서 "풀스크린" 태그다운 고정 구도가 유지된다.
- **소개 사진이 미션 배경이 된다.** 흰 소개 아래 컨테이너 폭(1296)으로 놓인 사진이 스크롤에 따라 화면 가득(1440)으로 넓어지고 그대로 고정 배경이 된다. 섹션 경계를 사진 하나가 넘어가서 "소개 → 하는 일"이 끊기지 않는다. 오른쪽 문장 3개가 지나가며 배경만 바뀌는 구조라, 문장을 읽는 동안 사진이 설명을 대신한다.
- **영문 Light(200) 큰 글자 + 한글 Light 본문의 한 가지 굵기.** 영문 제목·버튼은 gibson 200~400, 한글은 HanwhaGothic Light 하나다. 굵은 글자가 화면에 거의 없어서 사진이 가장 무거운 요소가 된다 — 방산·우주 회사인데도 위압감 대신 "미래·지속가능" 쪽 인상이 난다.
- **하위 페이지 틀이 다섯 가지로 정리된다.** 사진 머리형(소개·연혁·인재상) · 가운데 영문 머리형(Sustainable·Discover·Protect·제품) · 큰 한글 제목 + 표형(IR·미디어·사업장) · 장 이야기형(Why) · 전시형(쇼룸). 45개 경로가 이 다섯 안에 들어간다.

## 5. 단점

- **가상 스크롤이 문서를 900px 로 만든다.** Locomotive 가 `html{overflow:hidden}` 에 내용 전체를 transform 으로 움직인다. 실측 문서 높이 900. 브라우저 찾기(Ctrl+F)로 아래쪽 글을 찾으면 화면이 안 따라가고, 스크롤바·스페이스바·`#앵커`·화면 캡처 도구가 어긋난다. 이 작업의 `capture-site` 도 첫 화면만 찍혔고 `record-motion` 의 스크롤 구간은 2.5초 만에 멈췄다.
- **휠 한 칸에 57px 만 움직인다.** 실측: 휠 300 → 57px(관성 감쇠). 7289px 홈을 끝까지 내리려면 휠을 100번 넘게 굴려야 한다. 휠 한 칸을 300px 로 받는 네이티브 스크롤이면 약 24칸이다.
- **보조 글자 대비가 낮다.** 날짜·비활성 메뉴 `#999` 는 흰 바탕 2.8:1, 미션 비활성 문장(흰 글자 opacity .3)은 `#00040e` 위 약 2.5:1 이다. 비활성 상태라도 읽어야 하는 문장이다.
- **3D 쇼룸이 열리지 않는 환경이 있다.** 이 컨테이너의 헤드리스 Chromium 에서 VIEW MORE 를 눌러도 캔버스만 생기고 장면이 나오지 않았다. 대체 경로(정지 사진 + 사양 목록)가 없어서, 3D 가 안 되는 기기에서는 쇼룸이 빈 화면이다.
- **연혁 157행이 한 쪽에 다 있다.** 시기 막대가 있지만 한 시기 안에서 연도 단위로 건너뛸 방법이 없다. 행마다 연도를 다시 적어 같은 연도가 여러 행 연달아 반복된다(첫 시기 맨 앞에 2024 행이 3개 연속).
- (모작 쪽 단점) 연혁 덧붙인 행이 규칙으로 만든 문장이라 "○○ 설계 변경 승인" 같은 틀이 여러 번 보인다. 원본 분량을 맞추려는 선택이었고, 실제 회사 연혁이라면 쓰지 않을 방식이다.

## 6. 수정안

1. **가상 스크롤 → 네이티브 + 관성 보정.** Locomotive 대신 Lenis(네이티브 위 lerp .1) 로 바꾼다. 문서 높이가 실제로 생겨 찾기·앵커·스크롤바가 돌아온다. 휠 한 칸 이동량 57 → 100px 안팎. 모작에 이렇게 반영했다.
2. **보조 글자 `#999` → `#767676`(4.5:1), 미션 비활성 opacity .3 → .5(5.3:1).** 모작에 반영했다.
3. **쇼룸에 3D 실패 대체.** WebGL 초기화가 3초 안에 안 되면 제품 사진 3장 + 설명 점(지금의 15개 문구)을 정지 화면으로 보여 준다. 모작의 사진 끌기 보기가 그 대체안이다.
4. **연혁을 연도로 묶는다.** 같은 연도 행을 하나의 연도 머리(98px 시기 제목보다 작은 36px) 아래로 모으면 연도 숫자가 157번 → 연도 수만큼만 나오고, 눈이 연도 단위로 건너뛴다.
5. **팝업 버튼 대비.** `#e4793a` 위 흰 19px 글자 3.0:1 → `#c25515`(4.6:1).

## 7. 왜 상을 받았나

- **방산·우주 기업을 "Storytelling" 사이트로 만들었다.** 같은 업종 사이트는 보통 제품 목록·뉴스·IR 의 나열이다. 이 사이트는 Why We Exist 에 장 3개짜리 이야기(표지 사진 → 콜라주 → 맺음)를 두고, 홈에서도 Protect · Sustainable · Discover 세 문장을 사진 한 장 위로 흘려 보낸다. 태그 Storytelling · Fullscreen 이 그것이다.
- **제품을 무기가 아니라 전시물처럼 보여 준다.** 흰 무대 위 렌더 + 끌어 넘기기(홈), 3D 전시관(쇼룸, 태그 360 · 3D). 자주포·장갑차를 같은 흰 바닥 위 조형물처럼 늘어놓아 업종의 무거움을 덜었다. 심사가 Creativity 에 10점(frieda-odagboyi)을 준 자리로 보인다.
- **기업 사이트 필수 화면(IR·ESG·공시)을 같은 틀로 정리했다.** 큰 한글 제목 + 2px 윗선 표 하나로 실적발표·IR 일정·공시가 같은 모양이라, 투자자 화면도 브랜드 화면과 같은 사이트로 보인다.
- 개별 심사 종합 점수는 5.00~8.90 으로 폭이 넓다. Usability 를 5~6 으로 준 심사가 있는데, 위 단점의 가상 스크롤(휠 한 칸 57px, 찾기·앵커 문제)이 깎인 자리로 보인다.
