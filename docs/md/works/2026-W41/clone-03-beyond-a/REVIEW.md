# REVIEW — BEYOND A. (자이 매거진)

- **어워드**: iF DESIGN AWARD 2025 Winner · User Interface (UI) · Digital Media Interfaces · https://ifdesign.com/en/winner-ranking/project/digital-magazine-beyond-a/687279
- **모작**: 새결 매거진 WITHIN H. (가상 건설사 새결건설) · 100쪽

---

## 왜 상을 받았나

iF 의 분야가 *그래픽*이 아니라 **UI(Digital Media Interfaces)** 다. 심사가 본 것은 화면 연출보다 **기업 콘텐츠를 잡지처럼 읽히게 만든 정보 구조**였을 것이다.

- **가장 위험한 선택**: 건설사 사이트인데 분양 정보·단지 홍보를 첫 화면에서 빼고, 메뉴를 INTERVIEW · MOMENTS · INSIGHT · FOCUS 네 가지 *읽을거리 갈래*로만 짰다. 브랜드 사이트의 관행(제품 → 혜택 → 문의)을 버리고 잡지 목차를 메뉴로 쓴 셈이다. 통한 이유는 모든 목록이 같은 카드(사진 2:3 · 분류 · 제목 · 소제목 · 설명 · 꼬리표)로 통일돼 어느 갈래에 들어가도 읽는 법이 같기 때문이다.
- **가장 공들인 곳**: 하위 메뉴. 전폭 띠로 열리지만 왼쪽 세로선과 글자가 **그 메뉴 글자의 x 좌표**에 붙어 내려온다(JS 가 열 때마다 `--sub-nav-anchor-x` 를 계산하고, 오른쪽 끝을 넘으면 안쪽으로 당긴다). 메뉴 여섯 칸이 균등 분할이라 칸마다 세로선 위치가 다르다. 모작에서도 이 계산을 옮기는 데 시간이 가장 많이 들었다.
- **모작해 보고 알게 된 것**: 움직임이 거의 없다. 녹화에 잡힌 애니메이션 서명은 로고 페이드, 슬라이드 페이드 700ms, 하위 메뉴 250ms 셋뿐이다. 대신 **간격이 엄격하다** — 섹션 머리 → 내용 24, 카드 세로 96, 블록 48, 기사 머리 → 본문 72, 4·8·16·24·48 배수 밖의 값이 없다. 사진을 전부 바꿔도 같은 사이트로 보이는 이유가 이 리듬이다.

## 장점

- **무엇**: 카드 사진을 2:3 세로로 고정하고 `object-position: center top` 으로 자른다.
  **왜 작동하나**: 인터뷰 사진(서 있는 사람)과 공간 사진이 섞여도 4열 격자의 윗선이 모두 맞는다. 위를 기준으로 잘라 얼굴·지붕이 잘리지 않는다. 302×453 칸이면 1440 화면에서 사진이 화면 높이의 절반을 차지해 잡지 펼침면처럼 보인다.
- **무엇**: 기사 첫 문단만 20px 굵은 파랑(`#0085ad`), 나머지 본문은 16px 검정, 본문 폭 800.
  **왜 작동하나**: 한 줄 약 45자로 한글 측정폭 안에 들어온다. 첫 문단 색만 바꿔 리드(lead)를 표시하므로 제목 → 리드 → 본문 위계가 굵기 하나 추가 없이 생긴다.
- **무엇**: 목록 머리에 분류 칩과 함께 **건수**(EXPERTS 27 · RESIDENTS 74)를 붙인다.
  **왜 작동하나**: 누르기 전에 그 분류에 얼마나 쌓였는지 안다. 101건짜리 목록을 12개씩 9쪽으로 넘기지 않고 칩 하나로 줄일지 판단할 수 있다.
- **무엇**: 모든 쪽 아래에 같은 안내 상자 세 개(참여 · 뉴스레터 · 소개)를 둔다.
  **왜 작동하나**: 기사 끝에서 다음 행동이 늘 같은 자리에 있다. 색(남색 · 파랑 · 베이지)이 행동 종류를 구분한다.

## 단점

- **무엇**: 카드 분류 글자 `#bec2c5` 와 설명 글자 검정 50%.
  **어떤 문제를 만드나**: 흰 바탕 대비 1.8:1, 3.9:1. 14px 글자라 AA 미달이다. 분류는 목록에서 갈래를 구분하는 유일한 글자인데 가장 흐리다.
- **무엇**: 파랑 상자(`#0085ad`) 위 흰 글자와, 그 위 ‘뉴스레터 구독하기’ 단추(흰 50% 바탕 + 흰 글자).
  **어떤 문제를 만드나**: 본문 4.2:1, 단추 글자는 약 1.9:1 이라 단추 이름이 거의 안 읽힌다.
- **무엇**: 이벤트 상세가 세로 1만 px 이상의 **이미지 한 장**이다(기간·경품·응모 방법이 그림 속 글자).
  **어떤 문제를 만드나**: 화면 읽기 프로그램이 내용을 읽지 못하고, 검색되지 않고, 모바일에서 글자가 이미지 축소율만큼 작아진다(390px 에서 본문 글자 약 7px).
- **무엇**: 사진 크게 보기를 `<a href="원본.png">` 로 건다.
  **어떤 문제를 만드나**: 스크립트가 늦게 뜨면 사진 파일로 이동해 버리고, 사이트 점검 도구가 사진을 쪽으로 센다(모작 검증에서도 걸렸다).

## 수정안

- **어디를**: 카드 분류·설명 글자.
  **어떻게**: 분류 `#6b7075`(4.9:1), 설명 검정 62%(5.9:1). 크기·굵기는 그대로.
  **왜 나아지나**: 회색 위계는 유지하면서 AA 를 넘는다. 모작에 적용했다.
- **어디를**: 파랑 상자.
  **어떻게**: 바탕 `#00789c`(흰 글자 5.0:1), 단추는 `#a9d4e3` 바탕 + `#002941` 글자(10:1).
  **왜 나아지나**: 상자 색 인상은 같고 단추 이름이 읽힌다. 모작에 적용했다.
- **어디를**: 이벤트 상세.
  **어떻게**: 포스터 위쪽 대표 이미지 한 장만 그림으로 두고, 기간·주제·경품·응모 방법은 HTML 글자(명조 20px, 행간 1.8)로 조판한다.
  **왜 나아지나**: 같은 모양으로 읽기·검색·확대가 된다. 모작은 이 방식으로 만들었다.
- **어디를**: 사진 크게 보기.
  **어떻게**: `<button data-src>` 로 바꾸고 원본 링크는 라이트박스 안에 ‘원본 보기’로 둔다.
  **왜 나아지나**: 스크립트가 없을 때만 다르게 동작하는 링크가 사라지고 키보드로도 같다.

## 재현하면서 배운 것

- 하위 메뉴를 전폭으로 열면서 글자를 해당 메뉴 아래에 맞추려면, 칸 왼쪽 좌표를 재고 **오른쪽 끝 넘침을 안쪽으로 당기는 한 줄**(`min(raw, nav폭 − 내용폭)`)이 필요하다. NEWSLETTER 처럼 하위 메뉴가 없는 칸도 있어 계산은 하위 메뉴가 있는 칸에서만 한다.
- 원본 페이드는 Swiper 가 슬라이드를 가로로 `-1280n px` 옮겨 겹쳐 놓고 opacity 만 바꾸는 방식이었다. `position:absolute` 로 겹치면 같은 결과를 계산 없이 얻는다.
- 해라체 본문(기사)과 합쇼체 안내(소개 한 줄·상자)를 섞으면 한 화면 문체가 둘이 된다. 박물관 방식처럼 층을 나눠 안내 층에 `data-layer="summary"` 를 붙이니 원본과 같은 두 목소리를 규칙 안에서 쓸 수 있었다. 원본 인터뷰 답변의 해요체는 모작에서 해라체로 바꿨다.

## 어긋난 채로 남은 것

- 인터뷰 사진: 원본은 입주민 얼굴이 주인공이다. 모작은 얼굴 없는 뒷모습·공간 사진이라 인물 기사 분위기가 조용해졌다.
- 영상: 네 카드가 같은 영상 하나를 튼다.
- 기사 수: 원본 약 280건 → 31건. 쪽 번호는 people·뉴스레터에서만 실제로 넘어간다.
- 이벤트 포스터: 원본의 금박 명조·보름달 일러스트 대신 사진 + 남색 막 + Noto Serif KR.
