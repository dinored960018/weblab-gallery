# REVIEW — 현대문학 누리집 (모작: 결문학)

- **어워드**: iF DESIGN AWARD 2023 Winner · Branding & Communication Design · Websites · https://ifdesign.com/en/winner-ranking/project/hyundae-munhak/569230

---

## 왜 상을 받았나

- **가장 위험한 선택**: 단행본 목록을 **화면 높이에 고정한 두 칸**으로 나누고, 넓은 칸만 따로 스크롤하게 한 것. 일반적인 출판사 목록(4열 격자 + 쪽 번호)을 버리고, 한 화면에 두 상표(현대문학 1008px · 폴라북스 432px)를 동시에 세웠다. 좁은 칸 전체가 다른 상표로 가는 문이 되어, 상표 전환 메뉴를 따로 둘 필요가 없다. 출판사의 두 얼굴을 레이아웃 자체로 보여 준 점이 브랜딩 부문에서 점수를 받았을 것이다.
- **가장 많은 공이 들어간 곳**: 홈의 색. 새 책 슬라이드 바탕을 책마다 표지에서 뽑은 짙은 색(초록 `rgb(18,115,25)`, 남색 `rgb(22,27,117)` …)으로 바꾼다. 2초 동안 슬라이드가 넘어가며 바탕색 면이 통째로 밀려 들어오므로, 사진 한 장 없이 표지 하나로 화면 전체의 분위기가 바뀐다. 모작에서도 이 색을 맞추는 데(사진 평균색 → 채도 2.1배 → 명도 70 이하) 가장 오래 걸렸다.
- **모작해보고 알게 된 것**: 단행본 띠의 ‘흐르는’ 느낌은 연속 애니메이션이 아니라 Swiper `speed 5000 · autoplay 500` 조합이다. 한 칸(385px)을 5초 동안 ease 로 옮기고 0.5초 쉰다. 그래서 완전히 멈추지도 일정하게 흐르지도 않고, 칸마다 살짝 숨을 쉰다. 녹화(`motion.json`)를 보기 전엔 CSS 마퀴로 오해했다.

## 장점

- **무엇**: 명조 제목 + 고딕 300 본문 두 가지만 쓰는 타이포.
  **왜 작동하나**: 섹션 제목(44px Noto Serif KR 400)과 본문(16px Noto Sans KR 300)의 크기 비가 2.75:1 이고, 그 사이 단계는 24px(책 제목) 하나뿐이다. 단계가 셋이라 어느 화면에서든 제목·책 이름·설명이 바로 구분된다. 문예지라는 성격이 명조 한 가지로 전달된다.
- **무엇**: 표지가 곧 이미지 체계.
  **왜 작동하나**: 사진 촬영 없이 책 표지만으로 홈·목록·상세·검색을 채운다. 표지는 출판사가 이미 가진 자산이라 운영 비용이 0에 가깝고, 새 책이 나오면 화면이 저절로 바뀐다. 월간 목록은 4열 260px, 표지화가 목록은 5열 220px 로 같은 표지를 크기만 바꿔 다시 쓴다.
- **무엇**: 왼쪽 위 모서리를 40px 잘라 낸 회색 판.
  **왜 작동하나**: 월간 블록 · 월간 상세 · 단행본 상세 · 베스트셀러 칸에 같은 모양을 반복한다. 장식 요소가 이것 하나라서 페이지가 달라도 같은 사이트로 읽힌다. 책장을 넘기려고 귀를 접은 모양으로도 보인다.
- **무엇**: 목록마다 같은 도구 줄(검색 막대 → 분류 탭 → 네모 ▼ 셀렉트 → 표 → `더보기 (1/n)`).
  **왜 작동하나**: 문학상 · 출신 작가 · 표지화가 · 소식이 모두 같은 순서라 한 번 익히면 다른 목록도 바로 쓴다. `더보기` 에 쪽수를 함께 보여 줘 목록이 얼마나 남았는지 알 수 있다.

## 단점

- **무엇**: 회색 글자 대비.
  **어떤 문제를 만드나**: 비활성 탭·플레이스홀더·표 머리에 `#999`(흰 바탕 2.8:1), 월간 목록 띠는 밝은 회색 사진 위 흰 글자(1.5:1). WCAG 4.5:1 에 못 미쳐 저시력 사용자는 월간 이번 호 목차를 읽기 어렵다.
- **무엇**: 헤더가 고정되지 않는다.
  **어떤 문제를 만드나**: 홈 4,184px · 약관 12,327px 를 내려가면 메뉴가 없다. 맨 위로 단추가 있지만 하위 페이지로 바로 갈 길이 없다.
- **무엇**: 단행본 목록의 화면 높이 고정 두 칸.
  **어떤 문제를 만드나**: 바깥 페이지와 안쪽 칸 두 겹 스크롤이 생긴다. 넓은 칸을 끝까지 내리면 휠이 페이지 스크롤로 넘어가 푸터가 갑자기 올라온다. 900px 보다 낮은 노트북 화면에서는 칸 안에서 보이는 표지가 두세 권뿐이다.
- **무엇**: 레이어·셀렉트가 `href="#"` 링크와 jQuery `display` 전환으로만 동작.
  **어떤 문제를 만드나**: 원본 셀렉트는 키보드로 열 수 없고 ESC 로 닫히지 않는다. 메가 메뉴도 호버 전용이라 Tab 으로 하위 메뉴에 갈 수 없다.
- **무엇**: 영상 7개가 모두 유튜브 iframe.
  **어떤 문제를 만드나**: 영상자료 한 페이지에서 iframe 7개를 한꺼번에 불러 첫 화면이 무겁고, 한 개는 저작권 차단 화면이 그대로 보인다(`refs/intro--video/00-full.jpg`).

## 수정안

- **어디를**: 회색 글자
  **어떻게**: `#999` → `#6b6b6b`, 표 머리 띠도 `#6b6b6b`, 월간 띠는 사진 위에 `rgba(0,0,0,.35)` 막을 깔거나 띠를 `#77736d` 로.
  **왜 나아지나**: 2.8:1 → 5.3:1, 1.5:1 → 4.5:1 이상. 모작에 이미 적용했다.
- **어디를**: 헤더
  **어떻게**: 스크롤 141px 이후 메뉴 칸(50px)만 `position:sticky; top:0` 으로 붙이고, 위 칸(91px)은 올라가게 둔다.
  **왜 나아지나**: 화면을 50px 만 쓰고 어느 위치에서든 메뉴에 닿는다.
- **어디를**: 단행본 두 칸
  **어떻게**: 칸 높이 고정을 풀고 넓은 칸은 일반 문서 흐름으로, 좁은 칸만 `position:sticky; top:0; height:100vh` 로 붙인다.
  **왜 나아지나**: 스크롤이 한 겹으로 줄고 두 칸 구성은 그대로 남는다.
- **어디를**: 영상자료
  **어떻게**: 썸네일 + 재생 단추만 먼저 그리고, 누를 때 iframe 을 넣는다(`loading="lazy"` 로는 부족 — 7개 모두 첫 화면 근처).
  **왜 나아지나**: 첫 로드 요청 수가 iframe 7개 분량(수 MB)에서 이미지 7장으로 준다.

## 재현하면서 배운 것

- 슬라이드 바탕색을 표지에서 뽑아도 표지 평균색 그대로는 칙칙하다. 원본 색은 평균색보다 채도가 두 배쯤 높고 명도는 낮다. 사진 평균색에서 채도를 올리고 명도를 누르는 두 단계를 거쳐야 원본처럼 표지가 바탕에서 떠 보인다.
- 원본의 ‘흐름’ 모션은 녹화 프레임만 보면 선형처럼 보이지만, `motion.json` 의 transform 기록(5000ms ease, 시작 −1540 → −1925)을 보면 칸 단위 ease 다.
- 석조 목록은 열마다 시작 높이(178 · 80 · 0)를 다르게 주는 것만으로 대부분의 인상이 나온다. 높이 계산 라이브러리(원본은 Masonry 계열)를 쓰지 않아도 3열 순서 배치로 같은 화면이 된다.
- 문예지 소개 글은 해라체가 자연스럽지만, 이 레포의 한국어 검사기는 사이트 전체 문체를 하나로 요구한다. 공지·안내가 합쇼체라 전부 합쇼체로 맞췄고, 창간사도 합쇼체로 고쳐 썼다.

## 어긋난 채로 남은 것

- 원본 영상 7개(실존 인물) → 정지 화면 + 재생 단추. 재생은 되지 않는다.
- 원본 지도(포털 지도 API) → 직접 그린 약도 SVG. 확대·이동은 없다(원본도 정지 이미지처럼 쓰이지만 실제 지도 타일이다).
- 서점 링크 · SNS 링크 · e북 보기는 바깥 주소라 `example.com` 또는 구독 안내 페이지로 보낸다.
- 모바일은 원본이 기기 판별(UA)로 같은 주소에 다른 마크업을 주는 방식이다. 모작은 미디어 쿼리 하나로 처리해, 1100px 이하 데스크톱 창에서도 모바일 화면이 나온다.
- 주간 현대문학은 원본이 현재 ‘연재 예정 작품이 없습니다.’ 빈 상태라 모작도 빈 상태를 따랐다(연재 목록은 소개 상자에만).
