## 왜 상을 받았나

- **가장 위험한 선택**: 히어로 아래쪽 3분의 1을 **사진 14장으로 만든 회전 원통**에 내줬다. 여행 템플릿의 첫 화면은 보통 풀스크린 사진 한 장 + 검색창이다. 여기는 배경 사진 위에 또 사진 카드를 원통으로 세워 50초에 한 바퀴씩 돌린다. 통한 이유: 이 원통이 WebGL 이 아니라 CSS `preserve-3d` + 키프레임 하나(`autoRun`)라 무겁지 않고, `perspective 2500px` · `rotateX(6deg)` 로 원근을 약하게 줘서 카드가 "떠 있는 엽서 진열대"로 읽힌다. 양끝 5% 마스크가 원통 뒤쪽을 지워 앞면 5~6장만 보인다. 투어 목록을 스크롤하기 전에 상품 사진을 열네 장 보여 주는 장치다.
- **가장 많은 공이 들어간 곳**: 카드 하나의 문법. 반경 12px · 테두리 .15 · 안쪽 24px 상자가 투어 상세 칸, 후기, FAQ 항목, 연락 카드, 블로그 카드, 왜 우리 카드까지 전부 같다. 투어 줄은 "글 칸 1 + 사진 2" 를 줄마다 좌우로 뒤집어 체커보드를 만든다. 22페이지인데 새 상자 모양이 하나도 없다.
- **모작해보고 알게 된 것**: 필터가 단순한 탭이 아니라 **체커보드를 다시 짠다.** Adventure 를 누르면 한 줄만 남는데 그 줄은 원래 위치(1번째 줄 = 글 칸 왼쪽)를 지키는 게 아니라 "보이는 첫 줄"로 다시 계산된다(Family 의 Swiss Alps 는 전체 보기에서 4번째 줄 = 글 칸 오른쪽인데, 필터 후엔 글 칸 왼쪽 — `refs/states/01-tour-tab3.jpg`). 모작도 보이는 순서로 좌우를 다시 매긴다.

## 장점

- **무엇**: 8px 바깥 테두리. 히어로·검정 투어 섹션·흰 영상 섹션·푸터가 전부 화면 끝에서 8px 떨어진 r12 판이다.
  **왜 작동하나**: 배경색이 바뀌는 섹션(f8 → 검정 → f8 → 흰)이 "판을 갈아 끼우는" 느낌이 된다. 섹션 경계가 선이 아니라 판의 모서리라 별도 구분선이 필요 없다.
- **무엇**: 헤더 로고가 페이지 바탕색(f8)으로 칠한 사다리꼴 노치 안에 있다.
  **왜 작동하나**: 히어로 사진 위에서도 로고 대비를 따로 걱정할 필요가 없다(진한 글 on f8 = 18.9:1). 메뉴 6개는 흰 글이지만 로고만은 사진 색과 상관없이 항상 읽힌다.
- **무엇**: 섹션 머리가 "(괄호 부제) + 56px 두 줄 제목" 하나뿐.
  **왜 작동하나**: (Our Tour) · (Explore Trip) · (Testimonial) · (FAQ) 가 목차 역할을 한다. 제목이 항상 두 줄이라 섹션 시작 높이가 일정하다(부제 24 + 간격 16 + 제목 127 + 아래 56 = 223px, 실측 같음).
- **무엇**: 등장 모션이 두 종류뿐 — 줄 단위 y25 페이드(제목), y40/60 페이드(블록·카드).
  **왜 작동하나**: 카드 3칸의 지연을 0 · 250 · 375ms 로 줘서 "글 → 사진 → 사진" 읽는 순서대로 올라온다. 움직임이 내용 순서를 알려 준다.

## 단점

- **무엇**: 모바일 메뉴가 열려도 배경이 스크롤된다.
  **어떤 문제를 만드나**: 메뉴 아래 히어로가 메뉴와 함께 움직여 메뉴가 떠다니는 것처럼 보이고, 손가락이 메뉴 밖을 스치면 페이지가 400px 내려간다(`refs/states/mobile.log` scroll-while-open 400).
- **무엇**: 현재 페이지 표시가 없다. `w--current` 클래스는 붙지만 밑줄은 `translate(-100%)` 그대로라 안 보인다.
  **어떤 문제를 만드나**: 페이지 히어로가 전부 "사진 + 큰 제목" 같은 틀이라, 메뉴에서 지금 어디인지 알 길이 없다.
- **무엇**: 같은 블록 반복. 후기 블록이 4페이지(홈·About·Tour·Gallery), FAQ 가 3페이지에 똑같이 들어간다.
  **어떤 문제를 만드나**: Gallery 사진 11장 바로 아래 같은 후기 카드가 또 나온다. 페이지 높이의 15~25% 가 반복 블록이다(홈 기준 후기 807 + FAQ 759 = 1566 / 7787 = 20%).
- **무엇**: 상세·글 본문 폭 832~1062px 에 16px.
  **어떤 문제를 만드나**: 한 줄 104~133자. 긴 일정 설명을 읽을 때 다음 줄 시작을 놓친다(impeccable `line-length` 실측).
- **무엇**: 폼 오류가 브라우저 기본 말풍선이다. 그리고 Email 은 필수가 아닌데 Phone 은 필수다.
  **어떤 문제를 만드나**: 말풍선은 한 번에 한 칸만 보이고 바로 사라진다. 예약 확인을 보낼 연락처로 메일을 받지 않는 구조라 실제 운영과 맞지 않는다.
- **무엇**: 원본 사진 다수가 생성 이미지(License 페이지에 "Lummi Ai" 명시) — 과포화된 주황 사구, 매끈한 하늘.
  **어떤 문제를 만드나**: 실제 장소를 파는 여행 사이트에서 실재하지 않는 풍경이 상품 사진 자리에 있다. 신뢰의 문제다.

## 수정안

- 모바일 메뉴: 열릴 때 `html { overflow: hidden }`, ESC·바깥 클릭 닫기 — **모작에 넣음**(접근성 최소선).
- 현재 페이지: 밑줄을 `aria-current` 에 고정(`translate(0)`), 1px — **모작에 넣음**.
- 반복 블록: 후기는 홈·Tour 두 곳만, Gallery 는 사진 뒤 바로 푸터. 홈 높이 7787 → 약 6980(−807).
- 본문 폭: 상세 본문 `max-width: 68ch`(≈ 600px), 일정 표는 832 그대로. 한 줄 104자 → 70자.
- 폼: Email 필수 + Phone 선택, 오류는 칸 아래 글(14px, #B3321F, 흰 위 5.9:1) — **오류 글은 모작에 넣음**, 필수 조합은 원본대로 둠.
- 사진: 투어마다 실제 촬영 사진 2장. 모작은 Unsplash 실사로만 채움.

## 재현하면서 배운 것

- **CSS 3D 는 lazy 이미지와 싸운다.** 링 사진에 `loading="lazy"` 를 걸었더니 390px 화면에서 14장 중 1장만 떴다. 브라우저는 변환 전 상자 위치(전부 같은 자리, 일부는 화면 밖)로 "보이는지"를 판단한다. 3D 로 돌리는 이미지는 미리 받아야 한다.
- **blur 재검사는 버튼을 민다.** 폼 칸을 떠날 때 다시 검사하면, 제출 버튼을 누르는 순간(mousedown → blur) 오류 줄이 사라지며 버튼이 21px 올라가고 mouseup 이 빗나가 제출이 안 된다. 클릭 테스트에서만 잡혔다. 입력하는 동안 검사로 바꿨다.
- **서체 폭은 재야 한다.** 처음 고른 Hanken Grotesk 로 제목이 세 줄이 됐다 — 원인은 서체가 아니라 내 문구 길이였다. 11개 서체로 "Explore The Best" 90px 폭을 재 보니 Hanken 625 / 원본 652 로 오히려 좁았다. 문구를 원본 글자 수(16 · 15자 두 줄)에 맞추니 두 줄이 됐다.
- **원본의 체커보드는 "몇 번째 보이는 줄"이다.** 필터 상태를 하나씩 찍기 전엔 DOM 순서로 좌우가 정해진다고 생각했다.

## 어긋난 채로 남은 것

- 서체: Saprona → Hanken Grotesk. About 문단 원본 5줄 / 모작 4줄, 후기 인용 줄바꿈 다름.
- 로고: 원본의 A 변형 세리프 → Cormorant Garamond 글자.
- 마퀴의 스크롤 연동 미세 가속(GSAP) → 일정 속도.
- 행간 1.25 → 1.3 (게이트), 20~32px 글이 줄마다 0.5~1.6px 더 넓다.
- 후기 숫자 글 등장에서 투명도 변화 없음.
- 사진: 원본 생성 이미지의 진한 주황 톤 → 실사라 전체가 조금 차분하다.
- 모바일(≤767) 세부: 원본 모바일 전용 레이아웃은 홈 첫 화면·메뉴·Tour 만 실측해 맞췄고, 나머지 페이지는 같은 규칙으로 쌓았다.
