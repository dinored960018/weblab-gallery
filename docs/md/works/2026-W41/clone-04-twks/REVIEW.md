## 왜 상을 받았나

- **가장 위험한 선택**: **홈 헤더를 화면 위가 아니라 첫 화면 한가운데(top 429px)에 놓았다.** 에이전시 사이트는 보통 맨 위 고정 헤더 + 큰 히어로 문구다. 여기는 히어로에 문구가 아예 없고(h1 은 `sr-only`), 메뉴 한 줄이 사진을 가로로 자른다. 스크롤하면 그 줄이 페이지와 함께 올라가 맨 위에 붙는다. 통한 이유: 작업 사진 15장이 3.6초마다 바뀌는 히어로에서 글자를 사진 위에 얹지 않고 "선 하나"로만 지나가게 해, 사진이 가려지지 않는다. 같은 헤더가 `mix-blend-mode: difference` 라서 흰 본문 위에선 검정, 사진 위에선 반전되어 색을 따로 정할 필요가 없다.
- **가장 많은 공이 들어간 곳**: 연락 흐름. "contact" 를 누르면 페이지가 아니라 오른쪽 패널이 열리고, 그 안에 현지 시각(초 단위)·날씨·영업시간 티커와 스위스 역 시계가 있다. 여기서 "Tell us about your project" 를 누르면 메신저처럼 말풍선이 하나씩 올라오는 13단계 설문이 된다(이름 → 회사 → 서비스 체크 → 급한 정도 슬라이더 → 자유도 슬라이더 → 경험 …). 보통의 문의 폼 8칸을 대화 13턴으로 나눠, 한 번에 한 질문만 보이게 했다.
- **모작해보고 알게 된 것**: 푸터. 스크린샷으로는 "검은 푸터 아래 글자로 된 표범"이지만, 실측하면 푸터는 `position: fixed` 로 처음부터 본문 밑에 깔려 있고(top 720 고정, `translate 80%`) 마지막 한 화면 동안 `80% → 0` 으로 올라온다. 그리고 푸터가 화면을 다 덮는 순간에만 헤더가 749ms 동안 위로 빠진다. 헤더가 숨는 조건이 "아래로 스크롤"이 아니라 "푸터 도착"이라는 건 휠을 25px 씩 굴려 재 보기 전엔 몰랐다.

## 장점

- **무엇**: 크기 단계가 셋뿐이다 — 52.8px(text-big) · 20px(본문·메뉴·제목 전부) · 16px(text-small).
  **왜 작동하나**: 카드 제목 h3, 섹션 제목 h2, 본문, 메뉴가 전부 같은 20px 이라 위계는 크기가 아니라 **회색(#8C8C8C)과 위치**로만 만든다(제목 검정 / 부제 회색, 이름 검정 / 작업 종류 회색). 78페이지를 만들면서 새 크기를 넣을 일이 없었다.
- **무엇**: 들여쓰기 1/6(16.67%)이 모든 문단의 첫 줄에 있다.
  **왜 작동하나**: 큰 문단이 전폭(1420px)이어도 첫 줄이 2열만큼 들어가 있어 "문단의 시작"이 그리드 위 한 점으로 고정된다. 상세 페이지 소개(5~7열)·서비스 설명·아카이브까지 같은 규칙이라 페이지가 달라도 같은 책처럼 읽힌다.
- **무엇**: 모든 구분선이 왼쪽부터 그려지는 1px 선(animated-border-t), 모든 버튼이 "선 + 글자 + →".
  **왜 작동하나**: 상자·그림자·둥근 모서리가 하나도 없다. 상호작용 신호가 선이 밀려나는 움직임(CTA 위 선 0 → 504px)과 화살표 교체뿐이라, 사진이 가장 강한 요소로 남는다.
- **무엇**: 필터가 결과 없는 옵션을 아예 숨긴다(원본 `availableServices/availableIndustries`).
  **왜 작동하나**: "Engagement" 를 고르면 Branding 이 목록에서 사라진다. 0건 화면을 만날 일이 구조적으로 없다.

## 단점

- **무엇**: 흰 바탕 위 회색 `#8C8C8C` (카드 부제, All projects, 필터 옵션, 아카이브 줄).
  **어떤 문제를 만드나**: **3.36:1**. AA(4.5) 미달인데, 이 사이트에서 회색은 "부제·비활성"이라는 정보를 실어 나르는 유일한 수단이다. 스스로 `--color-grey-02-inverted: #737373`(4.74:1)을 정의해 놓고 흰 바탕에 쓰지 않았다.
- **무엇**: 채팅의 파란 말풍선 `#0077FF` 위 흰 글.
  **어떤 문제를 만드나**: **4.14:1** — 폼 라벨과 선택지 문장이 전부 이 위에 있다.
- **무엇**: 헤더가 `difference` 합성이라 중간 밝기 사진 위에서 글자가 사라진다.
  **어떤 문제를 만드나**: 상세 페이지 갤러리를 지날 때 회색·채도 낮은 사진 위에서 메뉴 대비가 1.1~1.9:1 까지 떨어진다(impeccable URL 검사 픽셀 최솟값). 내비게이션이 사진에 따라 읽혔다 안 읽혔다 한다.
- **무엇**: services 메뉴가 `<span>` 이고 하위 메뉴가 `:hover` 로만 열린다. 연락 패널은 ESC 로 안 닫히고 포커스도 가두지 않는다.
  **어떤 문제를 만드나**: 키보드 사용자는 Branding·Campaign·Digital 에 메뉴로 갈 수 없다. 패널이 열린 동안 Tab 이 뒤 페이지로 빠진다(`refs/states/05b-contact-after-esc.jpg`).
- **무엇**: 영어판 메뉴의 Campaign 이 404.
  **어떤 문제를 만드나**: 주 메뉴 세 항목 중 하나가 깨진 링크다(`refs/vp/services--campaign/00.jpg`).
- **무엇**: 본문 20px 의 행간 1.2(24px), 텍스트 문단이 좌우 10px 까지 붙는 전폭.
  **어떤 문제를 만드나**: 전폭 52.8px 문단 한 줄이 110자를 넘는다(홈 소개). 긴 글이 많지 않아 버티지만 Agency 처럼 4~5줄이 되면 줄 찾기가 어렵다.

## 수정안

- **어디를**: 흰 바탕 회색 글. **어떻게**: `#8C8C8C` → `#737373`(이미 있는 토큰), 검은 바탕은 `#8C8C8C` 유지. **왜 나아지나**: 3.36 → 4.74:1, 화면 인상은 거의 그대로. (모작에 적용)
- **어디를**: 채팅 말풍선. **어떻게**: `#0077FF` → `#0060D1`. **왜 나아지나**: 4.14 → 5.84:1, 같은 파랑 계열. (모작에 적용)
- **어디를**: 헤더. **어떻게**: 상세 갤러리 구간에선 `difference` 대신 흰 바탕 띠(높이 42, 불투명도 .92)를 깔거나, 사진이 헤더 아래로 지나갈 때만 `backdrop-filter: blur(12px)` + 반투명 흰색. **왜 나아지나**: 최솟값 1.1:1 → 15:1 이상. 홈 히어로의 가운데 헤더(이 사이트의 정체성)는 그대로 둘 수 있다.
- **어디를**: services · 연락 패널. **어떻게**: `span` → `button aria-expanded`, `:focus-within` 로도 열기, 패널에 ESC·포커스 가둠·복귀. **왜 나아지나**: 키보드로 모든 페이지에 도달. (모작에 적용)
- **어디를**: 큰 문단. **어떻게**: 전폭 대신 최대 1100px(약 70자), 행간 1.0 → 1.05. **왜 나아지나**: 줄 길이 110자 → 70자. 대신 그리드 끝까지 차는 포스터 같은 인상은 줄어든다 — 원본이 의도적으로 고른 것이라 홈 첫 문단만 남기고 나머지에 적용하는 쪽이 낫다.

## 재현하면서 배운 것

- **헤더 하나로 두 배경을 처리하는 법**: `color: white` + `mix-blend-mode: difference`. 흰 페이지에선 검정, 검은 푸터에선 흰색, 사진 위에선 반전 — 페이지마다 헤더 색을 바꾸는 JS 가 필요 없다. 다만 회색 글자를 합성하면 결과 밝기가 예상과 다르다(흰 바탕에서 `#8C8C8C` 는 `#737373` 으로 보임). 흐린 줄 대비를 맞추려면 **합성 후 색**으로 계산해야 했다(`#A6A6A6` → 흰 바탕 `#595959`).
- **푸터를 본문 밑에 깔기**: 본문(`main`)에 흰 배경과 높은 z-index, 푸터는 `fixed` + 아래에 한 화면 높이 빈 칸. 푸터 이동량은 "남은 스크롤 / 화면 높이" 하나로 끝난다.
- **원본 분량을 맞춰야 높이가 맞는다**: 처음엔 프로젝트 18 · 글 16 · 아카이브 69줄로 만들었더니 Archives −71%, Insights −45%. 원본 개수(37 · 44 · 284)의 90% 안팎으로 채우니 전부 ±15% 안에 들었다. 레이아웃이 아니라 내용 분량이 높이를 결정하는 사이트다.
- **문자열 치환에서 `$$` 는 `$` 가 된다**: JS `String.replace` 의 치환 문자열에서 `$$` 는 특수 문법이다. 고객·아카이브 코드를 고치다 `$$('li')` 가 `$('li')` 로 바뀌어 스크립트 오류가 났고, impeccable URL 검사(`script-error`)가 잡았다.

## 어긋난 채로 남은 것

- 서체: GT Standard(유료) → Albert Sans. 같은 줄바꿈이 나오지 않는 문단이 있다(Agency 첫 문단 원본 5줄 / 모작 4줄).
- 스크롤 아코디언의 높이 스크럽, Lenis 관성 스크롤.
- 히어로 영상 4칸, 상세 갤러리의 영상, 연락 패널 재생 목록 영상.
- 푸터 동물의 실제 걸음(영상) — 직접 그린 실루엣이라 표범보다 단순하다.
- 실제 인쇄물·브랜딩 사진 → 스톡 사진 + 직접 짠 표지 패널. 원본만큼 "작업물" 로 읽히지는 않는다.
- 차이 합성 헤더가 회색 사진 위를 지날 때의 대비(원본 구조, 위 단점).
