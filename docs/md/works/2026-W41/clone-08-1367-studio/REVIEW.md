# REVIEW — 1367 Studio

- 원본: https://www.1367studio.com/ · CSS Design Awards WOTD 2026-10-09 (JPANEL 8.42)
- 모작: `4082 Studio` · 16페이지 · http://localhost:4432/
- 비교 그림: `refs/cmp-home.jpg`(홈 13장면 원본|모작), `refs/cmp-pages.jpg`, `refs/cmp-detail.jpg`, 모션 `refs/motion-compare.html`

## 왜 상을 받았나

1. **첫 화면이 하나의 장면으로 이어진다.** 로드 때 사진 틀이 55%에서 화면 전체로 커지고(2.6s), 스크롤하면 그 사진 속으로 들어가 렌즈의 주황이 화면 전체가 되고, 그 주황이 그대로 브랜드 색 문장 배경이 된다. 500vh 를 쓰는 동안 장면이 끊기지 않는다. 심사 태그 "animated · parallax · scroll" 이 전부 이 구간에 있다.
2. **색이 세 개뿐이다.** 흰·검정·주황 `#f43c00`. 구역이 바뀔 때마다 이 셋이 번갈아 바탕이 되고(흰 집중 분야 → 흰 지구본 → 어두운 프로젝트 → 검정 CTA → 주황 푸터), 헤더 알약은 반투명 검정 하나로 어느 바탕 위에서도 읽힌다.
3. **에이전시 사이트의 정보가 짧고 정확하다.** 서비스 6줄에 하위 항목 3개씩, 사무소는 지구본 위 시계로, 프로젝트는 2개만. 심사위원이 "무엇을 하는 곳인가"를 30초 안에 안다.
4. **작은 상호작용이 많다.** 알약 축소, 줄 호버 미리보기, 6초 막대, 지구본 카드 크기 변화 — 하나하나는 300ms 이하지만 손에 닿는 곳마다 반응한다.

## 장점

- **헤더 알약 전환.** 맨 위에서는 화면 폭 1144px 의 투명한 줄이었다가 10px 만 내려도 682px 반투명 알약으로 줄어든다(600ms `cubic-bezier(.65,0,.35,1)`). 숨지 않아 언제든 메뉴에 닿고, 폭이 줄어 사진을 덜 가린다.
- **집중 분야 목록.** 한 줄이 진하고 나머지는 opacity .3. 커서를 올리면 그 줄이 진해지고 332px 미리보기가 커서를 따라온다. 6줄이 한 화면에 다 들어가고, 무엇을 고르고 있는지 위치로 보인다.
- **지구본이 사무소 목록을 대신한다.** 유럽 세 도시 → 남미 한 도시로 돌아가며 현지 시각을 보여 준다. 주소 목록보다 "세 시간대에서 일한다"가 빨리 전달된다.
- **하위 페이지가 같은 틀을 쓴다.** 모든 페이지가 같은 CTA(검정) + 푸터(주황, 화면 폭 숫자)로 끝나서, 페이지가 짧아도 끝이 분명하다.
- **블로그 필터가 대표 글을 건드리지 않는다.** 필터는 아래 5개 카드에만 걸리고 대표 글은 그대로 남아, 필터를 바꿔도 페이지 머리가 흔들리지 않는다.

## 단점

- **주황 위 흰 글자 대비 3.8:1.** 버튼(12px mono 600), 푸터 링크(16px), 문의 페이지 전체가 AA 미달. 문의 페이지의 칸 안 글(18px placeholder)이 가장 읽기 어렵다.
- **히어로 제목의 difference 합성.** 베이지 위에서는 남색이 되지만 사진이 바뀌거나 영상이 늦게 뜨면 색을 예측할 수 없다. 셋째 줄은 회색이라 대비가 더 낮다.
- **mono 대문자 문단.** About 상단의 12px 대문자 4줄, 히어로 오른쪽 4줄은 읽는 글인데 라벨처럼 썼다. 단어 모양이 사라져 읽는 속도가 떨어진다.
- **폼 오류가 브라우저 말풍선뿐.** 빈 칸으로 제출하면 첫 칸에만 말풍선이 뜨고 사라진다. 어느 칸이 문제인지 남지 않는다.
- **무게.** three.js + three-globe(149KB) + USDZ 뷰어(163KB)가 홈에 실린다. 지구본은 선 그림이고 3D 물체는 280px 이라 쓰임에 비해 크다.
- **Lenis + 고정 구간 2개(5vh·2.8vh).** 휠 한 번에 움직이는 양이 구간마다 달라 처음 보는 사람은 히어로에서 "안 내려간다"고 느낀다.

## 재현하면서 배운 것

- **장면 전환은 한 요소의 transform 하나로 만든다.** 원본 히어로의 "사진 속으로 들어가 주황이 된다"는 사진 scale + 주황 덮개 opacity 두 값뿐이다. 확대 곡선을 `z^2.2` 로 주면 처음엔 천천히, 끝에서 빨리 들어가 "빨려 들어가는" 느낌이 난다. 기준점(transform-origin)을 렌즈 중심에 두는 것이 전부다.
- **sticky 안의 형제는 쌓임 맥락을 먼저 본다.** 두 번째 프로젝트 패널이 transform 을 갖는 순간 쌓임 맥락이 생겨, 첫 패널 안의 `z-index:1` 글이 그 위로 올라왔다. 클릭 테스트의 호버가 실패해서 알았다. 각 패널에 z-index 를 명시해야 한다.
- **WebGL 지구본은 정사영 공식 세 줄이면 된다.** x = cosφ·sinΔλ, y = cosφ0·sinφ − sinφ0·cosφ·cosΔλ, z(앞뒤 판정)만 있으면 위경선과 도시 카드 위치가 나온다. 원본처럼 "윗부분만 보이는 큰 공"은 중심 위도를 −12° 로 두고 반지름을 화면 폭의 0.61배로 잡으면 된다.
- **스톡 컨테이너 사진은 거의 전부 로고다.** 밀착 시트 크기에서는 안 보이던 MAERSK · MSC 가 원본 크기에서 보였다. 사진 검수는 시트 + 원본 크기 두 단계가 필요하다.

## 어긋난 채로 남은 것

- 히어로 피사체가 다르다(인물 → 선글라스). 원본의 "인물이 돌아서는" 동작은 없다.
- 지구본은 선만 있고 3D 깊이(뒤쪽 선 흐림)가 없다. 앞면만 그린다.
- 3D 물체는 CSS 막대 3개라 원본 USDZ 의 둥근 빨간 덩어리와 모양이 다르다.
- Lenis 관성 스크롤을 뺐다. 휠 한 번의 이동량이 원본보다 크다.
- 주황이 원본보다 한 단계 진하다(`#d93500`).
- 메뉴 열림 모양: 원본은 알약에서 패널로 형태가 바뀌고, 모작은 위에서 아래로 잘라 펼친다.
- 로고 글자 `4082` 는 이미지가 아니라 Geist 700 글자다.
