# REVIEW — THE GLIM (글림) 회사 사이트

- **어워드**: Awwwards Honorable Mention (2025-11-10) · https://www.awwwards.com/sites/the-glim
- **모작**: Plok / (주)플록 (가상 UI/UX 회사) · 25페이지

---

## 왜 상을 받았나

수상 페이지가 꼽은 요소는 셋이다 — ‘Brief interaction’, ‘Moving Navigation’, ‘Contact Form’. 셋 다 화려한 3D 가 아니라 **회사 사이트의 흔한 부품(메뉴·소개·문의)을 장난감처럼 만든 것**이다.

- **가장 위험한 선택**: 메뉴를 알약 하나로 줄이고 페이지마다 그 알약의 위치를 바꾼 것(홈 가운데, Glimmer 오른쪽, Brief 왼쪽, 상세에서는 화면 아래 막대). 내비게이션 위치를 고정하는 관행을 깼다. 통한 이유는 메뉴 항목이 세 개뿐이고, 현재 메뉴가 늘 맨 위 칸에 색(빨강·초록·파랑)으로 표시돼 어디에 있는지 헷갈릴 일이 없기 때문이다. 같은 세 색이 팀 카드(UXP 초록 · UXD 빨강 · UXI 파랑), 지원 탭, 스티커에도 반복돼 색이 곧 메뉴 체계가 된다.
- **가장 공들인 곳**: 문의·지원 대화상자. 다섯 단계 번호와 점선, 칸마다 빨간 오류 문구, 약관 미동의 때만 뜨는 ‘Wait!’ 상자, 앞자리 고르기, 파일 첨부까지 한 화면에 들어 있다. 모작에서도 기능 60개 중 18개가 이 두 대화상자에 몰렸다.
- **모작해 보고 알게 된 것**: 홈의 화려함은 대부분 **영상 안에 있다**. 원본 CSS 가 실제로 움직이는 것은 캐러셀 활성 카드의 height·radius 300ms 하나뿐이었다(녹화 서명 5개 전부 이 카드). 패널 세 장이 미끄러지는 장면, 로고가 글자 단위로 나타나는 장면은 mp4 다. 정지 사진으로 바꾸자 홈은 조용해졌고, 그때서야 레이아웃 자체(전면 사진 + 왼쪽 아래 60px 제목 + 오른쪽 아래 유리 캐러셀)가 얼마나 단순한지 보였다.

## 장점

- **무엇**: 캐러셀의 활성 항목만 160×205 카드로 펼치고 나머지는 70px 원으로 둔다.
  **왜 작동하나**: 프로젝트 35개를 584px 띠 하나에 넣으면서도 지금 보고 있는 프로젝트의 이름·고객사·연도·분류·기술 꼬리표가 늘 같은 자리에 있다. 원 사이 간격 20, 카드 양옆 간격 20 으로 펼쳐질 때 이웃 원이 45px 씩만 밀려 시선이 흔들리지 않는다.
- **무엇**: 분류 필터가 캐러셀과 바둑판 두 보기에 같이 걸린다.
  **왜 작동하나**: 보기 방식을 바꿔도 고른 분류(예: CX 5건)가 유지된다. 알약 맨 위 칸에 ‘CX ⁵’처럼 개수까지 보여 결과가 몇 건인지 열기 전에 안다.
- **무엇**: 상세 페이지는 오른쪽에 정보 카드(분류·고객사·날짜·기술·수상)와 팀 카드를 두고, 본문은 1420px 전폭 사진으로 흘린다.
  **왜 작동하나**: 사례 연구에서 읽는 사람이 먼저 찾는 ‘누가·언제·무엇으로’가 첫 화면 오른쪽 360px 안에 다 있다. 아래 떠 있는 막대(이전·목록·다음·좋아요·공유)가 스크롤 어디서든 같은 자리라 사례를 연달아 넘겨 보기 쉽다.
- **무엇**: 폼 오류를 칸 안 오른쪽 위 12px 빨간 글자로 표시하고, 약관만 별도 상자로 막는다.
  **왜 작동하나**: 빈칸 다섯 개를 한 번에 보여 주므로 한 번 고치고 다시 보내면 끝난다. 상자는 칸 문구로 표시할 수 없는 동의 체크에만 쓴다.

## 단점

- **무엇**: 흰 글자를 `#ff0000` 위에 올린다(메뉴 알약 · 좋아요 · UXD 카드).
  **어떤 문제를 만드나**: 대비 4.0:1. 15px 굵은 글자는 큰 글자 기준(18.66px 굵게)에 못 미쳐 AA 미달이다. 검정 바탕 위 `#0000ff` 글자(UX Interactive Group 제목)는 2.4:1 로 더 낮다.
- **무엇**: 내부 스크롤러(`.scrollbar__scroller`)로 페이지 전체를 감싼다.
  **어떤 문제를 만드나**: 문서 높이가 900 으로 고정돼 브라우저 기본 스크롤·Space·End 키·찾기(Ctrl+F) 후 위치 이동이 스크롤러에 따라 달라진다. 원본 상세는 13,605px 를 이 상자 하나로 굴린다.
- **무엇**: 홈 배경이 프로젝트마다 mp4 영상이고, 첫 화면에 3개가 함께 들어온다.
  **어떤 문제를 만드나**: 첫 로드가 무겁다(측정 중 홈 `load` 30초 초과 1회, Brief 첫 화면은 3.9초 뒤에 그려짐 — `refs/motion-origin-brief/frames/load-03875`). 영상 안의 로고·문구는 화면 읽기 프로그램에 전달되지 않는다.
- **무엇**: 구성원 카드 호버가 이름을 감추고 한마디로 바꾼다.
  **어떤 문제를 만드나**: 호버 중에는 이름을 읽을 수 없다. 원본 상태 규칙은 `.people-item:hover` 만 있고 `:focus` 규칙이 없어(`refs/origin.md` 상태 규칙) 한마디는 마우스로만 볼 수 있다.
- **무엇**: 원본 Contact 의 지도는 카카오맵 SDK, 수상 리본·SNS 는 외부 스크립트다.
  **어떤 문제를 만드나**: 지도가 없는 홈에서도 구글 지도 SDK(102KB)를 불러오고(`refs/origin.md` 큰 스크립트), Brief 에서는 카카오·구글 지도 SDK 를 함께 불러온다.

## 수정안

- **어디를**: 빨강·파랑 면 위 글자
  **어떻게**: 빨강 `#ff0000` → `#e00000`(흰 글자 5.0:1), 검정 위 파랑 글자 `#0000ff` → `#5c6bff`(5.0:1). 색 이름(빨강·초록·파랑)의 인상은 유지된다(모작 반영).
- **어디를**: 내부 스크롤러
  **어떻게**: 문서 스크롤로 되돌리고 스크롤바만 `scrollbar-width: thin` 으로 얇게. 푸터·아래 막대는 `position: fixed`.
  **왜 나아지나**: 키보드·찾기·뒤로 가기 시 스크롤 위치 복원이 브라우저 기본 동작으로 돌아온다(모작 반영).
- **어디를**: 홈 배경 영상
  **어떻게**: 활성 프로젝트 1개만 `preload="metadata"` + 포스터 이미지, 나머지는 캐러셀에서 고를 때 불러오기. 영상 안 로고 문구는 `aria-label` 로.
  **왜 나아지나**: 첫 화면 전송량이 영상 1개 분으로 준다.
- **어디를**: 구성원 카드
  **어떻게**: 카드를 `tabindex=0` 으로, 한마디는 이름 아래 한 줄로 추가(이름을 지우지 않음).
  **왜 나아지나**: 키보드로도 보이고, 호버 중에도 이름이 남는다(모작은 포커스만 반영).

## 재현하면서 배운 것

- **하이재킹 스크롤처럼 보여도 휠이 아무것도 안 바꿀 수 있다.** 측정 도구가 홈을 ‘하이재킹’으로 표시했지만, 휠을 굴린 녹화 프레임을 보면 프로젝트는 그대로이고 패널 세 장이 미끄러지는 것은 배경 영상 내용이었다. 프레임을 직접 보지 않았으면 휠로 넘기는 기능을 지어냈을 것이다.
- **‘원본에만 있는 모션’이 0이 되지 않는 이유가 게이트일 수 있다.** 원본 활성 카드의 height 전환은 impeccable 이 레이아웃 전환으로 잡는다. clip-path 로 같은 크기·시간을 내면 화면은 같지만 녹화 서명은 다르게 남는다. 서명 표만 보고 ‘못 옮겼다’로 읽지 않도록 SPEC 에 대응 관계를 적었다.
- **검사기는 SVG `<text>` 의 색을 CSS `color` 로 읽는다.** 약도 안 글자(fill `#222`)가 흰 글자(상속 color)로 잡혀 대비 1.1:1 로 나왔다. 글자가 든 그림은 이미지 파일로 빼는 게 맞다.
- **키프레임 이름도 검사 대상이다.** 원본 이름 `aniFaceBounce` 를 그대로 쓰자 ease-in-out 인데도 탄성 이징으로 잡혔다.
- **Playwright 창이 가려지면 전환·스크롤 이벤트가 멈춘다.** 호버 검사 6개가 실패했는데 코드 문제가 아니라 렌더 프레임이 안 나와서였다. `bringToFront` 와 스크린샷으로 프레임을 강제하자 60/60.

## 어긋난 채로 남은 것

- **영상**: 홈 배경 3개 · Glimmer 영상 → 정지 사진. 홈의 움직임 대부분이 빠진다.
- **목록 수**: 프로젝트 35 → 12, 구성원 약 39 → 20. Glimmer 문서 높이 82%.
- **대표 이미지 성격**: 원본은 휴대폰 목업·브랜드 로고가 든 화보, 모작은 글자 없는 건축·정물 사진 + 영문 프로젝트명 글자. 사례 연구 사이트의 ‘화면을 보여 주는’ 인상이 약하다.
- **이모지·미모지**: Apple 이모지 이미지 → Noto Color Emoji 글꼴. 평면적이라 원본의 입체 이모지 인상과 다르다.
- **지도**: 카카오맵 → 정적 약도. 확대·이동 없음.
- **원본 Brief 떨어지는 동작의 수단**: 확인하지 못해 프레임 경로로 근사.
- **System 0건 화면**: 원본에서 직접 눌러 보지 않았다. 모작은 빈 상태 문구.
