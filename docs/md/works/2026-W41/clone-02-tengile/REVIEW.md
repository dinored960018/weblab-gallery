## 왜 상을 받았나

- **가장 위험한 선택**: **사파리 숙소 사이트인데 화면 대부분이 크림색 빈 바탕이다.** 업계 사이트는 보통 풀스크린 사진을 연달아 깐다. 여기는 히어로와 끝 사진만 풀블리드이고, 나머지는 12열 위에 사진을 4~6열 크기로 엇갈려 놓고 사이를 비워 둔다(홈 인트로: 왼쪽 568 폭 표범이 오른쪽 685 폭 코끼리보다 380px 아래에서 시작). 통한 이유: 야생 사진은 원래 정보가 많아서 한 장씩 떨어뜨려야 각 사진이 "본 것"으로 읽힌다. 크림 바탕(#F5EEE9)은 사바나 흙빛과 같은 계열이라 사진 테두리가 튀지 않는다.
- **가장 많은 공이 들어간 곳**: 장(章) 단위로 읽히게 만든 숙소 상세. 13,600px 짜리 페이지를 Overview · Lodge Details · The Suites … 8장으로 나누고, 화면 아래 가운데에 "‹ 현재 장 › Book your stay" 막대를 띄워 지금 어디인지와 예약 버튼을 늘 보이게 한다. 같은 막대가 Gallery 에서는 분류 전환기로 다시 쓰인다 — 부품 하나로 두 가지 탐색을 해결했다.
- **모작해보고 알게 된 것**: 사진 구름(Conservation 예고). 스크린샷으로는 "작은 사진 6장이 흩어져 있다"뿐인데, 녹화해 보면 6장이 전부 화면 가운데 한 점에서 출발해 `clip inset 99% → 0` 으로 열리면서 각자 좌표(−312,−251 등)로 퍼진다. 스크롤 진행값 하나(`--p`)에 위치와 잘림을 함께 묶은 것이라, 모작도 CSS 변수 하나로 같은 움직임이 나왔다.

## 장점

- **무엇**: 서체 두 개, 크기 단계 다섯 개(120u · 48u · 32 · 20 · 16/14)뿐.
  **왜 작동하나**: 히어로 대문자 세리프 → 녹색 큰 문단 → 32px 세리프 → 16px 본문 순서가 모든 페이지에서 같다. 34페이지를 만들면서 새 크기를 추가할 일이 없었다 — 원본의 체계가 그만큼 닫혀 있다는 뜻이다.
- **무엇**: 녹색 하나(`#5C6E21`)의 역할을 넓게 쓴다 — 큰 문단 글자, 푸터 바탕, 버튼 호버, 선택된 필터, 달력 선택일, 프리로더 막.
  **왜 작동하나**: 강조색을 하나로 묶어 "녹색이면 지금 고른 것/중요한 것"이라는 규칙이 페이지 사이에서 유지된다. 덕분에 크림·진녹·녹 세 색으로 사이트 전체가 끝난다.
- **무엇**: 버튼이 "라벨 칸 + 화살표 칸" 두 개로 나뉘고, 호버 때 두 칸 모두 모서리가 2px → 12px 로 둥글어지며 녹색이 된다.
  **왜 작동하나**: 평소엔 각진 종이 라벨처럼 조용하다가 손을 올렸을 때만 형태가 바뀌어, 누를 수 있다는 신호가 색만이 아니라 모양으로도 전달된다.
- **무엇**: 이야기·숙소 카드의 태그(Article · Wildlife / 9 Suites · Lodge)는 호버·포커스 때만 아래에서 올라온다(500ms, 두 번째 150ms 늦게).
  **왜 작동하나**: 목록을 훑을 때는 사진과 제목만 보이고, 관심을 보인 카드만 추가 정보를 낸다 — 카드 수가 많아도 화면이 붐비지 않는다.

## 단점

- **무엇**: 흐린 글 `#A5A593` (Location·Highlights 라벨, 인용 출처, 폼 안내 글).
  **어떤 문제를 만드나**: 크림 바탕 위 **2.18:1**. WCAG AA(4.5) 의 절반. 정보 라벨이 전부 이 색이라 저시력 사용자는 표의 열 제목을 못 읽는다.
- **무엇**: 녹색 푸터 아래 줄의 `#E3E1D4`.
  **어떤 문제를 만드나**: **4.31:1** — 14px 글씨라 AA 미달. 개인정보·약관 링크가 이 줄에 있다.
- **무엇**: 투명 헤더의 크림 글자(Enquire · Menu)가 히어로 사진 밝기에 그대로 맡겨진다.
  **어떤 문제를 만드나**: 모작에서 같은 덮개(위 .38)로 재 보니 밝은 하늘 사진에서 3.5:1 까지 떨어졌다. 히어로가 영상이라 컷마다 대비가 바뀐다.
- **무엇**: 본문 Inter 16/20(행간 1.25), 히어로 설명 18/19.8(1.1).
  **어떤 문제를 만드나**: 숙소 상세의 긴 설명(8~10줄)에서 줄 사이가 붙어 다음 줄 찾기가 어렵다.
- **무엇**: 원본 히어로는 영상 + 커서 라벨("Play Video")로만 영상 모달을 연다.
  **어떤 문제를 만드나**: 히어로 전체가 버튼이라 키보드·터치 사용자는 그 존재를 알기 어렵다. 라벨은 마우스를 올려야만 보인다.

## 수정안

- **어디를**: 흐린 글. **어떻게**: `#A5A593` → `#6B6B55`. **왜 나아지나**: 같은 올리브 회색 계열로 4.74:1 — 모작에 적용함.
- **어디를**: 푸터 아래 줄. **어떻게**: 크림 `#F5EEE9`. **왜 나아지나**: 4.93:1 — 모작에 적용함.
- **어디를**: 히어로 덮개. **어떻게**: 위쪽 14% 를 `rgba(20,22,10,.72) → .3` 로. **왜 나아지나**: 사진 히어로 19곳 전부 헤더 글자 뒤 대비 p90 4.9:1 이상(픽셀 실측). 사진 본체는 거의 그대로 — 모작에 적용함.
- **어디를**: 작은 글 행간. **어떻게**: 16/21, 18/23.6, 20/26.4, 14/18.4. **왜 나아지나**: 1.3배 이상. 32px 이상 디스플레이 세리프(1.1·1.15)는 원본 인상을 지키려고 유지 — 모작에 적용함.
- **어디를**: 영상 열기. **어떻게**: 히어로 버튼에 `aria-label="Play film"` + `aria-haspopup="dialog"`, 포커스 링, Enter 로 열기. 모바일에서는 라벨을 늘 보이게. **왜 나아지나**: 키보드로도 같은 기능에 닿는다 — 앞 두 가지는 모작에 적용, 모바일 상시 라벨은 원본에 없어 적용 안 함.

## 모작하며 막힌 곳

- **Newsreader 와 Fragment 의 폭 차이**: 같은 글자 크기로 두면 "PLAN YOUR STAY"·"PARTNER HUB" 가 화면 밖으로 넘쳤다. 원본은 큰 제목이 늘 좌우 여백까지 꽉 차므로, 고정 크기 대신 글자 폭을 재서 화면 폭에 맞추는 계산으로 바꿨다. 대문자 윗부분이 줄 상자에 잘리는 문제도 그때 같이 잡았다.
- **사진 번호가 밀리는 문제**: 안 쓰는 사진 파일을 지우자 분류 안의 번호가 당겨져 가로 자리에 세로 사진이 들어갔다. 분류별 장수를 채택 시점에 고정(`refs/photo-pool.json`)하고 나서야 지워도 배치가 그대로였다.
- **Pinterest 의 AI 이미지**: 침실·라운지·노을은 결과 대부분이 AI 렌더였다. 실사로 보이는 것만 남기고 Unsplash 로 보충했다(SPEC 사진 절).
